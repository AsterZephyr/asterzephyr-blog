做大模型训练的团队大多认同数据决定上限，但一落到具体的清洗和配比决策，做法往往截然相反。同一个网页池子，有的团队把 95% 以上的原始语料筛掉才敢送进集群，有的团队则会搬出 2026 年的新实验，认为算力足够大时根本不该强过滤。到了数据验收环节，一边是人工抽看几十条样本就拍板上线，另一边坚持先训代理模型跑排序。这些互相冲突的经验，最后常被统称为**数据 Taste（数据品味）**。

最近，Datumwell 创始人 Allen 在 X 上发了一篇[《什么是好的数据 Taste?》](https://x.com/allen_datumwell/status/2123813175644782633?s=19)，把 2019 年到 2026 年的十余篇代表工作串在了一起。顺着这份清单逐篇核对原始论文、技术报告和实验前提，能看出分歧的根源：**行业里常把“好数据”当成文本自带的绝对标签，但同一批语料在不同算力、阶段和校验条件下，实际价值会完全翻转。**

要把模糊的“数据 Taste”落到日常工程决策里，靠的是一套前置定位：动管线之前，先确认自己处在四条边界的哪一侧，即算力与唯一 token 的比例区位、当前所处的训练阶段、有没有低成本信号替代肉眼抽查，以及在自然语料见底后，能否把合成质量交给可执行环境和验证器把关。

## 为什么一线团队总觉得“数据品味”像玄学

看算法和缩放律之前，两项针对真实工程团队的实证调研，能直接解释为什么大家习惯把数据判断叫作 Taste。

ASE 2024 的实证研究[《What Makes a High-Quality Training Dataset for Large Language Models: A Practitioners’ Perspective》](https://dl.acm.org/doi/10.1145/3691620.3695061)先访谈了 13 位资深 LLM 从业者，随后调研了来自 23 个国家的 219 名一线工程师。在 18 项候选特征里，从业者把**可靠性（Reliability）、相关性（Relevance）、准确性（Accuracy）和合规性（Compliance）**排在最前，而把完整性、均衡性、完全无重复、一致性和时效性放在末尾。他们反馈最多的痛点有三类：缺少统一的数据处理流程，说不清洗到哪一步才算够用，洗完之后也缺乏可靠的量化指标。

同年，Google Research 在 CHI 2024 扩展摘要[《Understanding the Dataset Practitioners Behind Large Language Model Development》](https://arxiv.org/abs/2402.16611)里访谈了内部 10 位跨工具链、建模和评测的从业者。即便在头部实验室，大家检查数据的方式也分成两个极端：一端是直接打开电子表格肉眼抽查（eyeballing），看前 10 条再随便翻翻中间；另一端是自己写高度定制的 Python Notebook 脚本，两者之间几乎没有通用工具。

论文指出了这种做法的风险：**自由抽查会放大确认偏误（confirmation bias）**。模型输出不对劲时，工程师往往带着预设结论去翻语料，总能挑出几条看起来很脏的样本来印证直觉，却无从判断这批样本在整个分布里究竟是噪声源、边际无关项，还是长尾里少见的有效信息。

要跳出靠直觉打补丁的循环，就不能笼统地问一份数据干不干净，得先把决定数据价值的四条边界拆开看。

## 边界一：算力和数据区位决定清洗是提分还是掉点

围绕网页数据到底该滤多狠，社区每隔一两年就会重吵一轮。把 2019 到 2026 年的实验放回各自的实验条件里看，表面上互相打架的论文，其实分别落在**算力受限**和**数据受限**两个不同区位。

起点是 DeepMind 的 Chinchilla 论文[《Training Compute-Optimal Large Language Models》](https://arxiv.org/abs/2203.15556)（2022）。作者跑了 400 余组覆盖 70M 到 16B 参数的实验，表明固定训练算力 $$C$$ 时，模型参数量 $$N$$ 与训练 token 数 $$D$$ 应近似同步按 $$C^{0.5}$$ 扩展；70B 参数配合 1.4T token 的 Chinchilla，在相近算力下击败了 280B 参数、仅训 300B token 的 Gopher。这也定了现代预训练的基调：算力固定时，把有限 FLOPs 花在信息密度更高的 token 上，提分非常直接。

顺着这条逻辑，早期网页清洗流水线的思路很直白。以 Meta 的 [CCNet](https://arxiv.org/abs/1911.00359)（2019）为例，它在 Common Crawl 上串联了三步：段落去重、fastText 语言识别，以及用维基百科训练的 5-gram KenLM 计算困惑度（perplexity），把文档切成高、中、低三档。早期原始网页里全是乱码、机器翻译和模板噪声，训练预算也远没触及数据上限，这类规则和语言模型过滤器几乎不会出错。

但到了万亿 token 规模，第一个反常现象出现了。Hugging Face 在 2024 年发布 [FineWeb](https://arxiv.org/abs/2406.17557)（基于 96 个 Common Crawl 快照构建的 15T token 语料）时，对去重策略做了系统消融，结果发现：**跨全部 96 个快照做全局 MinHash 模糊去重，下游评测反而显著掉点。**

作者追查 `2013-48` 快照找到了原因。全局迭代去重从最新快照往旧快照一路删重，砍掉了早期快照约 90% 的数据，全量语料被压缩到 4T token。他们把这一快照里被保留的 10%（约 31B token）与原本被删掉的 90% 独立去重后的版本（171B token）分别拿去训消融模型，结果**留下来的 10% 效果反而比被删掉的 90% 更差**。人工抽查发现，真正有价值的常青内容往往反复出现在多个历史快照里，跨快照全局去重把它们清掉了，反而在旧快照里把只出现过一次的广告页、关键词堆砌和破损网页给上采样了。改为**单个快照内部独立 MinHash 去重**（保留 20T token，再叠加启发式过滤得到 15T）后，模型成绩才追平并赶上 RefinedWeb。

这个实验说明，FineWeb 并没有否定过滤和去重本身（后面的 FineWeb-Edu 分类器就带来了大幅提分），问题出在**无差别的跨快照硬砍悄悄改变了剩余样本的分布**。

2026 年 5 月，斯坦福团队（Mohri、Duchi 与 Hashimoto）在 [《A Bitter Lesson for Data Filtering》](https://arxiv.org/abs/2605.19407)（NeurIPS 2026）里把视角转向了**高算力、数据稀缺（high-compute, data-scarce）**区位。主流强过滤器删得非常狠，DCLM-Baseline 只保留原始 Common Crawl 池子的约 2.1%，RefinedWeb 也只保留约 13%。为了在可控算力下复现算力充裕但唯一 token 见底的处境，作者将 240T token 的 DCLM-Pool 随机等比缩放到 670M 到 10B token 的固定池，用 15M 到 7B 稠密 Transformer 对比未过滤池与五种过滤方案（停用词、去重、英文过滤、RefinedWeb、DCLM-Baseline），在 C4、FineWeb-Edu 与 Cosmopedia 上测负对数似然（NLL）。

曲线在放大规模后发生了交叉。在 15M 小模型或低算力阶段，严格过滤的数据明显占优；但在 670M 固定池上，模型扩大到约 330M 及以上、训练步数拉长后，**完全不过滤的原始池反超了全部五个过滤子集**，成为 Pareto 最优。作者还做了一组垃圾注入实验：在干净池里刻意掺入词序被打乱的低质量文本后，330M 模型在训练约 11B token 时，表现竟然超过了不掺杂的干净池。这符合容量角度的解释：参数足够大、步数足够长时，模型不仅能把噪声隔离在内部子空间里，还能从打乱词序的文本中榨出词汇共现等残余统计信号。

<Callout type="warning" title="别把“数据过滤的苦涩教训”误读成明天就删掉清洗流水线">
[arXiv:2605.19407](https://arxiv.org/abs/2605.19407) 本身写明了三个前提条件，脱离它们外推就会得出错误的工程结论：<br />
1. **交叉点极远**：作者按缩放律外推，针对完整 240T Common Crawl 池子，未过滤数据反超 RefinedWeb 的算力交叉点在大约 $$10^{30}$$ FLOPs，远高于当前绝大多数团队的训练预算。在算力受限区位，过滤和精选依然是第一杠杆。<br />
2. **固定静态池假设**：实验假设数据池固定、不引入高质量合成扩张。实际工业界面对低质量原始语料，越来越多团队选择拿去改写、蒸馏或结构化重组，而不是直接裸训。<br />
3. **仅限稠密预训练 NLL**：实验不含课程学习、退火阶段和后训练对齐，也没覆盖风格酷似高质量文本但事实错误的对抗性毒化数据。
</Callout>

即便留在预训练里，多留数据也不等于随便混合。MIT、华盛顿大学、斯坦福与 Google 团队联合发表的 [ATLAS](https://arxiv.org/abs/2510.22037)（2025 年 10 月提交，ICLR 2026，[Google Research 博客解读](https://www.research.google/blog/atlas-practical-scaling-laws-for-multilingual-models/)发布于 2026 年 1 月）跑了 774 组实验，横跨 10M 到 8B 参数和 400 多种语言，测出了三条定量规律：跨语言迁移具有强方向性，作者实测 $$38 \times 38 = 1,444$$ 对语言的互助矩阵，发现西班牙语、葡萄牙语对加泰罗尼亚语帮助很大，但 $$A \to B$$ 有效并不代表反过来 $$B \to A$$ 对称有效；正迁移还能抵消一部分多语言诅咒，在不损失单语性能的前提下把支持语言数从 $$K$$ 翻倍到 $$2K$$，参数量只需扩到 **1.18×**、总数据扩到 **1.66×**、总算力扩到 **1.96×**，单语分摊的数据量甚至降到原来的 **83%**；但印地语、斯瓦希里语这类资源稀缺语种一旦超过 **1 个 epoch**，重复数据的边际收益就会快速衰落，损失曲线明显上翘。

算力紧、池子大时，过滤是压缩冗余最划算的手段；池子固定、算力过剩时，过严的硬砍会提前撞上数据墙。无论处在哪个区位，跨语言迁移方向和重复 epoch 上限都得按实测来配。

## 边界二：预训练、退火、SFT 和 RL 要的数据信号并不一样

团队里另一类常见混淆，是拿预训练的习惯做 SFT，或者把 Mid-training（退火与继续预训练）和 SFT 当成一回事。此前在 [Mid-Training 那篇文章](/blog/llm-mid-training-被tech-report遮掩的关键训练阶段/)里拆过，很多前沿模型的能力跃迁发生在预训练末期的退火和长上下文扩展，而非后训练。翻开具体配方就能看到，各阶段的优化目标原本就不在同一个维度上。

NVIDIA 的 [Nemotron 3 Nano (30B-A3B)](https://arxiv.org/abs/2512.20848)（2025 年 12 月）在公开报告和 [Nemotron 开源配方](https://github.com/NVIDIA-NeMo/Nemotron)里把数据阶段划得很清楚。这里先纠正一条社区里常见的转述错误：报告里的 **23.5T 与 1.5T 共同构成 25T 预训练的两个阶段，并不是 1.5T 的 SFT**。四个阶段的分工如下：

1. **Pre-training Phase 1（23.5T token）**：占预训练前 94%，覆盖网页、代码、数学、多语言和合成数据等 15 个大类，重心在广度和多样性。
2. **Pre-training Phase 2 / 退火（1.5T token）**：切换至高质量精选语料，大幅抬高推理与准确性权重。
3. **Long-Context 继续预训练（121B token）**：采用 NoPE 将上下文外推到 1M。NVIDIA 发现只用 `512k` 超长序列训练会让短上下文评测轻微下滑，于是刻意混入 **`512k` 与 `4k` 序列**，配方为 20% 长文档问答、1% 最高 256k 的合成检索任务和 79% 下采样的 Phase 2 数据。其中长上下文合成任务会把关键证据拉远、分散在多篇文档里并塞入干扰项，同时保留可自动验证的标准答案。
4. **SFT（约 18M 样本）与推理控制**：进入 SFT 后，模型不再只是拟合广义语料的 $$p(x_t \mid x_{<t})$$，还要学会多轮工具调用、状态与动作切换以及可控推理协议。Nemotron 3 Nano 第 3.1.5 节披露了一个具体的构造方式：随机抽 **10%** 的 SFT 样本剥离思维链，教模型在关闭思考模式时直接作答；再随机抽 **3%** 的 SFT 样本把思考轨迹截断到不同 token 预算长度，后面直接接回原本的最终答案。这样到了线上推理，一旦触达用户设定的思考预算，服务端强行插入 `</think>` 闭合标记，模型就能基于不完整的思考平稳收敛出答案。

推理预算可控靠的是提前写进 SFT 数据分布里的行为协议，单靠线上强截断行不通。类似的阶段互补也出现在 [DeepSeek-R1](https://arxiv.org/abs/2501.12948)（2025 年 1 月初版，2026 年 1 月修订）里：纯 RL 训出的 R1-Zero 虽然自发涌现了反思和长思考，但伴随可读性差和中英混杂；R1 先注入冷启动高质量 SFT，再在 RL 阶段联合优化准确性、格式和语言一致性奖励，并辅以拒绝采样回流 SFT，才把能力和可用性同时拉齐。

即便只看 SFT 阶段的**指令数据筛选（Data Selection）**，数据池规模变大之后，原本好用的方法也会失效。2023 年底至 2024 年由香港科技大学主导，联合上科大、北邮及美团、阿里研究者发表的 [DEITA](https://arxiv.org/abs/2312.15685)（ICLR 2024，常被简称为某单厂论文，实为多机构合作）用 LLM 打分刻画**复杂度 × 质量 × 多样性**，在 7B/13B 模型上仅凭 6K 条精选样本就追平甚至超过十倍体量的开源对齐数据。

到了 2025 年，艾伦人工智能研究院（Ai2）和华盛顿大学等团队在 [《Large-Scale Data Selection for Instruction Tuning》](https://arxiv.org/abs/2503.01807)里把候选池从常见的 100k 到 200k 扩大到 **580 万条**（从中选出最高 250 万条），结果发现：**过去在小池上表现很好的多种方法（Perplexity、IFD 以及部分外部 Embedding 筛选）在百万级池子里性能退化，甚至跑输随机采样。** 池子越大，外置打分器自身的偏好漏洞就越容易被极端样本钻空子。

论文据此提出基于**待微调基座模型自身最后一层隐状态**的 **RDS+** 方法：对完整指令和回复序列做前向传播，考虑到因果掩码下靠后的 token 汇聚了更多上下文，采用位置加权平均池化：

```math
e = \sum_{i=1}^{L} w_i h_i, \qquad w_i = \frac{i}{\sum_{j=1}^{L} j}
```

其中 $$h_i$$ 为第 $$i$$ 个 token 的最后一层隐状态，$$L$$ 为序列长度。随后计算候选样本与验证查询集的余弦相似度，并以多任务轮询（round-robin）方式去重采样。实验显示，RDS+ 在 200k 扩到 5.8M 池子时收益持续放大，超越了人工精调的 Tülu 2 和 Tülu 3 SFT 混合集。算上抽取隐状态的额外算力，只要筛选规模超过约 32.6 万条，它的综合算力效率就优于随机采样；甚至用 1.5B 到 70B 的跨家族小模型抽特征也能保持不错的迁移性。

## 边界三：不烧全量预训练，怎么用低成本信号测数据好坏

没有团队烧得起每改一次数据配比，就重训一遍几十 B 甚至万亿参数的主模型。缺便宜、可复现的提前评估手段，大家才会退回 Google Research 论文里记录的肉眼看 10 条。

2025 年的三篇代表论文走了三条不同的低成本估值路线，分别面向**语料级 A/B 排序**、**文档级语义打标**和**端到端元学习估值**。

### 1. DataDecide：用 0.01% 算力的连续概率做语料级排序

Ai2 等团队发表于 ICML 2025 的 [DataDecide](https://arxiv.org/abs/2504.11393) 建了一套对照基准：在 25 份来源、去重与过滤策略不同的预训练语料上，横跨 4M 到 1B 参数（14 个尺寸、最多 100B token、3 个随机种子）一共训了 1,050 个模型，专门检验小模型实验能不能准确预测大模型上哪份语料会赢。

论文给出的两条结论直接影响预训练消融的设计。一方面，**单尺度小模型直接排序就能打平复杂的缩放律外推**：只用 150M 模型对两两语料排座次，预测 1B（100B token）目标模型胜负的平均准确率就达到约 **80%**；论文测试的 8 种缩放律外推基线，在算力与决策准确率前沿上都没超过这种简单的直接排序。另一方面，**别盯着离散 Accuracy，改看连续概率代理指标**：小模型在 MBPP、HumanEval 这类代码题上几乎答不对，pass@1 接近 0，直接拿准确率排语料跟扔硬币没区别。但如果改测模型给正确答案续写分配的**按字符归一化连续概率**（`Correct Prob`），或者所有候选答案的总概率（`Total Prob`），在目标模型**仅 0.01% 的算力**下，MMLU、ARC、HellaSwag、MBPP 和 HumanEval 的语料排序预测准确率就能超过 **80%**。小模型虽然还做不对题，但概率质量已经提前暴露出语料有没有带来对口的领域曝光。

DataDecide 也标出了自己的盲区：**对于常见数学基准，无论换哪一种连续概率指标，小模型预测依然接近随机水平**。而且它回答的是整份语料 A 和 B 谁更强，不负责给单条文档打分。

### 2. DataMan：把大模型的静态判断蒸馏成 1.5B 语义裁判

如果目标是给万亿级语料做文档级细粒度清洗和领域配比，浙大与阿里 Qwen 团队发表于 ICLR 2025 的 [DataMan](https://arxiv.org/abs/2502.19363) 是一条容易落地的工业路线。

团队先用“反向思考”让 GPT-4-turbo 分析高困惑度与低困惑度极端文档的成因，归纳出 **13 项独立质量维度**（准确性、连贯性、语言一致性、语义密度、知识新颖度、主题聚焦、创造性、专业度、风格一致性、语法多样性、结构规范性、原创性、敏感性），外加 **1 项综合分（Overall Score）** 和 **15 个应用领域标签**。随后用 GPT-4-turbo 标注约 35.6 万篇文档（与人类专家一致性超 95%），微调出基于 **Qwen2-1.5B** 的轻量打分器，离线给 447B token 的 SlimPajama 打满标签。仅取最高分（5 分）的 30B token 训 1.3B 模型，就击败了 QuRating 基线，并超过了多用 50% 数据的均匀采样模型。

这条路线成本低、可解释，也方便按领域和质量矩阵调配比例。短板在于它**固化了教师模型的静态品味**，既可能继承强模型的风格偏见，也感知不到目标模型在训练中期到底缺哪一类梯度信号。

### 3. DataRater：用双层元梯度，让验证集直接教小模型给样本估值

如果不想靠人工或 GPT-4 写死文档好坏标准，Google DeepMind 在 NeurIPS 2025 发表的 [DataRater](https://arxiv.org/abs/2505.17895) 给出了端到端的双层优化解法。

社区里常把 DataRater 误解为“拿原模型 loss 当标签，专门挑能产生更大梯度的样本”，但那样很容易挑中脏数据和难样本噪声。它实际用的是**双层优化（bi-level optimization）**框架：打分器本身是一个 50M 参数的非因果 Transformer $$\phi_\eta$$，负责给训练微批次里的每条样本输出归一化权重；内层循环由 8 个 400M 语言模型组成的种群在加权批次上执行 $$T=2$$ 步参数更新；外层循环拿更新后的内层模型去测**互不相交的留出验证集损失**，再借助 `MixFlow-MG` 混合模式微分技术，把外层验证损失的**二阶元梯度**反向传回打分器参数 $$\eta$$。

DataRater 实际奖励的是**训完之后最能让目标验证集掉 loss 的样本**。元训练完成后，只需用这个 50M 打分器对候选批次做 Top-K 淘汰。实验发现，50M 评测下找到的最优淘汰比例（C4 丢 10%、C4/noclean 丢 50%、The Pile 丢 75%）在 50M、150M、400M 直到 1B 模型上都保持稳定；在 The Pile 与 C4/noclean 等噪声较重的语料上，能带来最高 **46.6% 的净算力（FLOPs）收益**。

它的局限同样明确：二阶元训练的系统复杂度和算力开销远高于 DataMan，且论文验证止步于 1B 目标模型。由 400M 内层模型学出的估值策略，跨过两个数量级迁移到百 B 级 MoE 模型上是否依然成立，目前还没有公开证据。

实际工程里，成熟团队多半把这三类手段**分层串联**：用 DataMan 这类蒸馏多维打标器做大规模文档初筛和领域编目，用 DataDecide 的连续概率小代理做语料级 A/B 门禁，只在噪声复杂、价值足够高的核心池子上考虑元学习估值。

## 边界四：自然语料见底后，合成数据靠环境与验证器把关

到了长程 Agent（连续写代码、调工具、逛网页、查报错、回滚状态）和多模态搜索，互联网上本来就不存在大量干净、完整、带正确反馈的公开轨迹。筛选的天花板就是存量的天花板，数据工程的重心自然转向**数据合成**。

先排除一条不可持续的捷径：窃取或灰产蒸馏闭源 API 的隐藏思维链。2026 年 8 月的 [《Stealing Reasoning Traces from Proprietary LLM APIs》](https://arxiv.org/abs/2608.09867)披露了一个实际存在的系统漏洞：多家闭源厂商为了保护知识产权，把隐藏推理过程加密成密文块返回客户端并在多轮请求中回传，但这些密文块在同一厂商的跨会话、跨模型体系里可以互换。攻击者把强模型的加密思考块注入同厂更弱、护栏更松的模型里，就能迫使其原样吐出明文。作者在 Anthropic、OpenAI 与 Google 上均复现了该缺陷，并从公开仓库抓取的 315,320 个推理块中解码出 367 条 PII 和 182 组凭证。这类漏洞很快会被封堵，也触及合规与安全红线，长期的数据能力不能押在蹭别人黑盒轨迹上。

2026 年夏季的三篇一线系统论文，展示了可规模化、可验真的合成数据引擎长什么样。它们都从真实材料起手，并把质量门控交给可执行环境或隔离验证器。

### 1. Kimi K3：层级知识图谱扩覆盖，隔离验证器防作弊

在 [《Kimi K3: Open Frontier Intelligence》](https://arxiv.org/abs/2607.24653)（2026 年 7 月底发布，8 月修订）里，合成数据横跨预训练与后训练两头：

预训练侧（§3.1）放大了知识与数学语料的多风格、多视角**改写（rephrasing）**流水线，要求逐块生成后对照原文做保真校验；同时大幅扩充**程序化多模态数据**，将代码与其渲染出的 SVG、3D 资产和网页成对绑定。

后训练 Agent 侧（§4.2）为了防止合成任务越造越雷同，团队构建了一个自演化的**层级知识图谱（DAG，原文称 Knowledge Graph 而非 Task Graph）**。从粗粒度种子概念出发，由 Agent 递归搜网探索子概念，入图前先检索复用已有等价节点以去重，所有有向边严格从粗概念指向细概念，直至概念足够原子化。合成任务时，从图谱不同粒度采样节点组合，结合祖先路径检索真实的论文、博客与代码仓库，再交由任务合成 Agent 生成跨多种可组合白盒 Harness（可模拟不同编程 Agent 脚手架）的任务。

质量门控核心在 §4.2.6 的自主执行任务（AET）：任务不附带参考轨迹，直接把**公开诊断验证器、隐藏留出验证器与提交预算惩罚**隔离封装，防止模型靠暴力试探或钻测试漏洞（reward hacking）骗分。

### 2. Qwen-AgentWorld：先用真实轨迹训语言世界模型，再可控放大模拟环境

真实沙箱、浏览器和外部 API 慢、贵、不稳定，而且接口间歇报错、分页截断、批量部分失败这类生产边界条件在常规运行中很难触发。Qwen 团队在 2026 年 6 月的 [《Qwen-AgentWorld: Language World Models for General Agents》](https://arxiv.org/abs/2606.24597)里换了思路：把环境本身训成模型。

团队先在 MCP、Search、Terminal、SWE、Android、Web、OS 这 7 个领域采集了 **1,000 万条以上真实环境交互轨迹**，经由 CPT → SFT → RL 三阶段训出 35B-A3B 和 397B-A17B 两款语言世界模型，按 $$p(o_{t+1} \mid o_{\le t}, a_{\le t})$$ 生成环境反馈，再用来驱动大规模**仿真强化学习（Sim RL）**。

在完全分布外的 OpenClaw 平台上，团队从少量真实轨迹提炼出可复用种子场景，沿状态变化和任务变体双轴合成 **4,000 个模拟环境**，零样本把 Claw-Eval 提升 **+4.3**、QwenClawBench 提升 **+7.1**；在 MCP 工具调用里，通过可控指令主动注入接口报错、分页和不完整返回等长尾扰动，把 MCPMark 平均分从 SFT 基线的 21.5 拉到 **33.8（+12.3）**，明显高于无扰动控制的仿真（24.6）；在搜索任务里，团队构建了 **1,000 个自洽的虚构关系数据库世界**（每个含 300 到 500 行结构化事实，用 SQL 提取真值、反向生成问句并强制无泄漏分段返回），在真实搜索评测 WideSearch 上提升 **+16.3**，甚至**反超真实在线环境 RL（50.3% vs. 45.6%）**。

论文同时点出了仿真合成的核心瓶颈：**初始状态锚定（Initial State Conditioning）**。给世界模型的种子初始状态越细（文件系统、账号配置、底层表结构），仿真保真度越高；一旦偷懒只给粗略 prompt，合成轨迹很快就会漂移失真。

### 3. WeAgent-MMSearch：从像素依赖终点逆向扩跳，按难度对比度筛题

多模态搜索 Agent 的合成数据有个常见问题：题面或网页 URL 偷偷泄了答案，模型根本没看图片，纯靠文本捷径就把题蒙对了。腾讯微信 AI 与中山大学在 2026 年 8 月的 [《WeAgent-MMSearch》](https://arxiv.org/abs/2608.28062)用四步逆向流水线堵住了这个口子：

1. **先锁定视觉终点（$$n_d$$）**：从 2026 年 1 到 7 月实时网页事件和维基百科中采集目标图片与视觉事实，准入条件是目标图必须在同构的 `WeAgent-Harness` 下可达，且答案严格依赖**可见像素**，在标题、URL 和图注里都查不到。
2. **逆向多跳扩张（$$n_0 \to \dots \to n_{d-1} \to n_d$$）**：不再从起点正向编题，而是从终点 $$n_d$$ 倒推 $$d \in \{2, 3, 4\}$$ 跳。每一步只给当前实体 $$n_i$$，让专家 Agent 搜网构造一个答案恰好指向该实体的前置问句，得到 $$n_{i-1}$$。
3. **桥接唯一性与防泄题审计**：剔除中间桥接不唯一、缺图或元数据泄题的候选链条。
4. **SFT 与 RL 分层筛样本**：SFT 仅保留专家在同构 Harness（支持检索图片持久化落盘与多轮回看）下**完整且答对**的轨迹（3.3K 自建 + 56.2K 归一化开源 = 59.5K）；进入 RL 前，对每条候选题目用 SFT 模型采样 **8 条 rollout**，**剔除 8/8 全对（无提升空间）和 0/8 全错（无组内对比奖励）的题目**，只留下 4.9K 精选自建提示词。

  caption="图源：Liu et al., WeAgent-MMSearch（arXiv:2608.28062，Figure 2）。只有让问题终点严格依赖可见像素，并把检索到的图像持久化进同构推理环境，才能堵死文本捷径，迫使模型学出真正的图文交替检索能力。"

三套方案的共同做法有三点：用真实材料或细粒度状态做锚点，防止模式坍缩；在结构上堵死捷径与泄题，避免伪难度；把质量门控交给隔离验证器或 rollout 通过率对比度，不依赖模型自评。

## 改数据管线前先答清五个问题

动任何一条数据管线之前，先拿证据答清下面五个问题，比凭直觉看样本或照搬某篇热门论文的单一结论靠谱得多：

<Steps>
  <StepItem title="瓶颈在算力，还是在唯一 token 上限？">
    算力吃紧时，质量过滤、领域配比和单快照去重（如 FineWeb、DataMan）仍是最高杠杆。一旦逼近固定池的多 epoch 瓶颈，就要警惕过严过滤和跨快照去重带来的隐性分布畸变（Bitter Lesson、ATLAS 的 1-epoch 拐点）。
  </StepItem>
  <StepItem title="这批数据要补知识、立行为协议，还是划定策略搜索边界？">
    不要用同一套标准要求预训练、退火、SFT 和 RL。参考 Nemotron 3 Nano 把思考开关和截断预算写进 10%/3% 的 SFT 数据、把 `512k`/`4k` 混进长上下文续训的做法，先明确目标行为协议，再反推数据形态。
  </StepItem>
  <StepItem title="数据池扩大一个数量级后，筛选器会不会被钻空子？">
    小池好用的外置打分器到了百万级往往放大裁判偏见（Ivison et al.）。扩大池子时，优先对比随机基线，考虑引入目标基座自身表征（如 RDS+）或显式多样性约束。
  </StepItem>
  <StepItem title="数据决策靠肉眼看 10 条，还是靠低成本可复现代理？">
    烧大集群之前，先搭语料级小模型代理（用 DataDecide 的连续概率而非早期离散准确率）与可追溯的数据版本对照，避免在电子表格里带着结论找证据。
  </StepItem>
  <StepItem title="合成样本的真值由谁拍板，大模型自评还是可执行环境？">
    对 Agent 和长程推理来说，难点在于搭出能被环境或真值严格验真的反馈链路（例如 Kimi K3 的知识图谱与隔离验证器、Qwen-AgentWorld 的细粒度种子状态、WeAgent-MMSearch 的像素终点逆向链条），而不是再多生成十万条看起来像推理的文本。
  </StepItem>
</Steps>

<Callout type="note" title="仍未有定论的三个开放问题">
基于目前公开文献，有三块关键地带还缺乏大规模实证结论：<br />
1. **元学习估值的百 B 级迁移**：DataRater 在 400M 内层模型到 1B 目标模型上证明了有效性，但迁移到百 B 级 MoE 和混合架构时，最优淘汰率与样本排序是否依然稳健，目前尚无公开验证。<br />
2. **数学与复杂推理的小模型可预测性**：DataDecide 显示连续概率能提前预测通用知识和代码语料优劣，但数学基准在小规模下依然接近随机，低成本预测高阶推理数据的代理指标仍是空白。<br />
3. **高算力下裸训长尾网页与算力换可验证合成的真实交叉点**：Bitter Lesson 讨论的是固定静态网页池，而前沿实验室正把越来越多算力投入到改写、图谱合成和世界模型仿真，这两条路线的最优算力分配比至今没有统一的公开缩放律。
</Callout>
