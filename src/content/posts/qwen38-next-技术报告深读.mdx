> 原报告：*On the Design of Qwen3.8-Next Architecture: Evaluation, Efficiency, and Training Stability*，Qwen Team，封面日期 2026-08-26，arXiv:2608.30320v1（2026-08-31）。<br />
> [官方 PDF](https://github.com/QwenLM/Qwen3.8-Flash-Next/blob/main/tech_report.pdf) · [arXiv](https://arxiv.org/abs/2608.30320) · [模型卡](https://huggingface.co/Qwen/Qwen3.8-Flash-Next)<br />
> 报告的对象是开放权重的架构预览版 Qwen3.8-Flash-Next。线上的 Qwen3.8-Flash 以它为基础另加了产品功能，那部分配置不是本文的证据。页码均指官方 PDF。

Qwen3.8-Flash-Next 的每一层都从四份并行保存的中间状态里取输入，算完再把结果写回这四份状态。报告说，这套结构在推理时的开销主要就是把这几份状态读进来、写回去的内存流量。团队注意到，训练好的模型里每层的写入通常集中在其中两份上，于是试过让每层只用门控值最高的两份，从头训练和训练中途引入都试了。预训练的 loss 和 benchmark 几乎没有变化，模型做完后训练，质量却明显下降，让不同层保留不同份数也没能挽回。这个省带宽的办法最后没有采用。作者在报告里专门记了一句：只看预训练指标，这里会做出错误的决定。（§2.2，PDF 第 14 页）

这份 28 页的报告里，类似的分歧还有好几处。有的改动让 loss 只降了一点，benchmark 却涨了一截；有的改动让 loss 一路下降，benchmark 却先停了下来；还有的改动改变了训练能承受多大的学习率。作者给每个候选改动定了同一套检查：loss 和下游 benchmark 一起看；成本按训练、prefill 和 decode 三个阶段分别算；再看它会不会移动最优超参数、会不会让训练变得不稳。（Introduction，PDF 第 1 至 2 页）

下面先沿着这些分歧看 Flash-Next 的结构怎样定下来，再看结构一变，优化器、学习率、batch size 和稳定性测试为什么都得重新来过。要我只挑两份报告来学大模型到底是怎样训练出来的，我会选这一份和 [MAI-Thinking-1 的技术报告](https://microsoft.ai/pdf/mai-thinking-1.pdf)。文中的测量都来自报告作者，示意图、从图上读出的近似数值和推算是本文做的，本文没有复现训练或推理。

## 125B、6B、51B 和九分之一各记的是哪本账

Flash-Next 是稀疏的混合专家（MoE）模型：每层有很多个专家网络，每个 token 只路由到其中少数几个。报告给出三个参数数字：总参数 125B，每个 token 激活 6B，另有 51B 参数在 n-gram embedding 表里，放在加速器之外的主机内存中。（Abstract；Table 11，PDF 第 22 页）官方模型卡还单列了 4B 的 MTP（多 token 预测）模块，报告正文没有拆出这一项。

这几个数字回答的是不同的问题。6B 是一个 token 前向计算时参与矩阵乘法的权重规模，大致决定每个 token 的计算量。125B 是要存下来的主干权重，没被选中的专家也得放在某处。51B 的表按地址查，每个 token 只取很少几行，计算量几乎可以忽略，但这些参数同样占存储，查到的行还要搬到加速器上。三个数加起来也换算不出显存需求，权重放在哪里、用什么精度存，报告都没有给。

和上一代旗舰 Qwen3.7-Plus（397B 总参数、17B 激活）的 Base 模型相比，Flash-Next-Base 在 14 项预训练 benchmark 中领先 8 项，落后的 6 项最多差 2.6 分。报告说这只用了约三分之一的激活参数和三分之一的训练 token，训练 FLOPs 约为九分之一。（Abstract；§4，PDF 第 23 页）

九分之一可以按常用的估算 `训练 FLOPs ≈ 6 × 激活参数 × 训练 token 数` 来理解：两个因子各约三分之一，乘起来约九分之一（6B 比 17B 约为 0.35）。这是本文的解读，报告没有公布两代模型各自用了多少训练 token。这是算术量之比，不是账单，也不是墙钟时间：同样的 FLOPs，硬件利用率、通信和优化器开销不同，花的时间和钱都不同。比较的也只是 Base 模型的预训练 benchmark，后训练之后的模型和推理服务的成本都不在这组数字里。

成本还要分阶段看。训练要对大批完整序列做前向、反向和优化器更新。推理时，prefill 一次读完整段输入，报告说这一阶段主要花在对整个上下文做注意力；decode 每一步只生成一个或几个 token，主要受内存读写限制，每一步都要把权重、缓存和状态读出来。（Introduction，PDF 第 2 页）同一个改动常常只帮其中一个阶段，后面各节都按这个区分记账。

整体结构见 Figure 1。输入 token 先查普通的词表 embedding，同时 n-gram 层用以当前 token 结尾的几个短 n-gram 去表里查向量，查到的结果从第 2 层加进来。主干每四层一组，三层 Gated DeltaNet（GDN），一层 QSA；按模型卡，全模型 48 层，也就是 12 组、12 个 QSA 层。每层有两个子层，先是 token mixer（GDN 或 QSA），再是 MoE。每个子层都先经过 GR Read 从四条残差分支（开头说的四份中间状态）读出输入，算完再经 GR Write 写回四条分支，细节放在后面讲。最后一次 GR Read 和输出前的归一化合在一起，结果交给预测头和 MTP 模块。

## 四层里留一层全注意力，RoPE 也留着

token mixer 决定一个位置能拿到哪些前文信息。全注意力让每个位置按内容直接去查之前的任何一个 token。处理一段 n 个 token 的序列时（训练或 prefill），两两打分的工作量随 n 平方增长；生成阶段每个新 token 要扫一遍全部历史，工作量随历史长度线性增长，KV cache 也随长度线性变大。滑动窗口注意力（SWA）每个位置只看最近的一段窗口，单个 query 的工作量和这一层要保留的 KV 都有上限，整段序列的总工作量仍随长度线性增长，窗口外的信息只能经过更多层间接传过来。GDN 走另一条路：每个头把前文压进一个固定大小的状态，每读一个 token 更新一次，单个 token 的读写成本不随历史变长。（§2.1.1，PDF 第 3 至 4 页）

GDN 的每个头维护一个状态矩阵 `S`，形状是 `d_k × d_v`，大小与已经读过多少 token 无关。第 t 个 token 到来时，先由输入算出 query `q_t`、key `k_t`（两者都做了 L2 归一化）和 value `v_t`，再按报告的 Eq. 1 至 4 更新：

```math
\begin{aligned}
\tilde S_{t-1}&=\alpha_t S_{t-1},\quad \alpha_t\in(0,1)\\
e_t&=v_t-\tilde S_{t-1}^{\top}k_t\\
S_t&=\tilde S_{t-1}+\beta_t k_t e_t^\top,\quad\beta_t\in(0,1)\\
y_t&=S_t^\top q_t
\end{aligned}
```

四行依次表示整体衰减、用 key 读出旧值并计算误差、只写回误差，以及用 query 读出当前输出。

`α_t` 和 `β_t` 都由当前输入算出：`α_t` 控制旧记忆整体保留多久，`β_t` 控制这一次改写多少。GDN 和普通线性注意力的区别在第二行，写入之前先用 `k_t` 查一下状态里已经记着什么，只写入预测误差。

举一个只为演示的小例子：`d_k = 2`、`d_v = 1`，两个互相正交的单位 key `k1 = (1, 0)`、`k2 = (0, 1)`。先取 `α = β = 1`，这是不衰减、完全修正的边界情形，真实的门输出落在 (0, 1) 之间，取不到这两个值。依次写入 k1→5、k2→2，然后再写一次 k1→3：

```text
写入 k1→5：误差 5 − 0 = 5，用 k1 读出 5
写入 k2→2：误差 2 − 0 = 2，k1 仍读出 5，k2 读出 2
写入 k1→3：误差 3 − 5 = −2，k1 读出 3，k2 仍读出 2
直接累加 k vᵀ、不做误差修正的线性注意力：k1 读出 5 + 3 = 8
```

同一个 key 再次出现时，GDN 改写的是旧关联，不会无限叠加。门不取边界值时，作用分别是衰减和部分修正，下面两种情况都从第三次写入后的状态出发。若 `α = 0.5`、`β` 仍取 1，写入前所有旧关联先减半，这时再写一次 k2→2，k1 读出 1.5，k2 仍读出 2。若保持 `α = 1`、只把 `β` 改成 0.5，这一次只修正一半误差，k1 从 3 写向 1，读出 2。

真实模型里 key 不会正好正交，状态容量也有限。报告的说法是，任何有限状态的循环记忆都很难精确复现逐 token 的直接检索，所以隔几层要放一层全注意力。q、k、v 进入递推之前还先过一个短的因果卷积，补一点局部信息；输出端，报告把原版 GDN 的 SiLU 门换成取值有界的 sigmoid 门，说在他们的实验里一致更好，但没有给数字。（PDF 第 4 页）

为什么用混合结构，报告给了一组同规模对照（Table 1，PDF 第 5 页）。模型是基于 Qwen3.5 架构的 28 层 25B-A3B MoE，先用 4K 长度训练 400B token，再用 32K 长度训练 80B token。纯全注意力版本在 9 项 benchmark 上平均 49.87；SWA 混合版每四层有三层是窗口 128 的 SWA，平均 51.15；GDN 混合版把这三层换成 GDN，平均 53.81。GDN 混合版在 9 项里有 8 项超过全注意力，例外是 EvalPlus；有 7 项超过 SWA 混合版，SWA 混合版在 MMLU 上略高，EvalPlus 更强。

作者自己说明，这组结果支持采用混合结构，但说明不了每一项提升来自哪个部件；这 9 项也都是短上下文 benchmark。至于每四层放一层全注意力在效率和质量之间平衡得比较好、周期性的全注意力对长上下文尤其重要，报告只给了结论，没有对应的比例消融表。

全注意力层里的位置编码，是做完后训练才定下来的。去掉 RoPE 的 NoPE 版本在预训练阶段和保留 RoPE 的版本几乎看不出差别，后训练之后却明显更容易陷入无休止的生成，停不下来。全注意力层因此保留了 RoPE。报告没有给出这组实验的规模和具体比例。（§2.1.1，PDF 第 4 页）

训练这一侧，GDN 的 kernel 用基于 TileLang 的 FlashQLA 重写。报告说在 NVIDIA GPU 的多种设置下，它的前向比 FLA 的 Triton kernel 快 2 到 3 倍，反向约快 2 倍，这是算子级的对比。（PDF 第 5 页）

## QSA：先给压缩块打分，读的仍是原来的 token

每四层那一层全注意力，在长上下文下仍是平方增长的开销。DeepSeek 的 DSA 先用一个轻量的索引器（indexer）给历史 token 打分，只对选中的 token 做注意力，可索引器本身要给每一对 query 和 key 打分，开销仍是 `O(n²)`，序列越长越显眼。QSA 让索引器只看压缩过的 key。它在继续预训练（continued pretraining，CPT）阶段引入，替换掉主干和 MTP 模块里所有的全注意力层。（§2.1.2，PDF 第 5 至 7 页）

跟着位置 `i` 上的一个 query 走一遍，报告的位置从 0 开始编号。索引器是一个很轻的多 query 注意力，4 个 query 头共用 1 个 key 头。key 按相邻 4 个 token 分成不重叠的块（压缩比 `r = 4`），每块取平均、做 RMSNorm，然后才加 RoPE（只作用在每个头 128 维中的 64 维），位置统一用块的起始位置 `4b`，query 保留自己的位置 `i`。先压缩再加位置，是为了不把旋转相位不同的向量平均到一起。

打分只针对已经完整出现的块：块 `b` 的最后一个 token `4b + 3` 不晚于 `i`，这个块才参与，分数是 4 个头上 ReLU 之后的内积之和。token 预算 `K = 2048`，每个 query 留下分数最高的 `2048 / 4 = 512` 个块，展开回原来的 token 下标；还没填满的那个块里已经出现的 0 到 3 个 token 总会加进来。核心注意力最后读的是这些原始 token 的 K/V，压缩后的块只用来打分。

```math
\begin{aligned}
\bar k_b=\operatorname{RoPE}\bigl(&\operatorname{RMSNorm}(\\
&\operatorname{mean}(k_{4b},\ldots,k_{4b+3})),4b\bigr)\\
I_{ib}&=\sum_h\operatorname{ReLU}(q_{i,h}\cdot\bar k_b)\\
B_i&=\operatorname{Top512}(I_{i,\cdot})\\
S_i&=\operatorname{expand}(B_i)\\
&\quad\cup\{4\lfloor(i+1)/4\rfloor,\ldots,i\}
\end{aligned}
```

RoPE 使用位置 $$4b$$；只对满足 $$4b+3\le i$$ 的完整块计算分数。$$B_i$$ 取分数最高的 512 个块；$$K=2048$$，$$r=4$$。展开这些块的原 token 后，再并入当前尚未完整的块。

拿 `i = 9` 走一遍。位置 0 至 3 和 4 至 7 是两个完整块，可以打分；8、9 所在的块还缺 10、11，不参与打分，已经出现的 8、9 作为尾部直接读入；10、11 还没生成，哪条路径都碰不到。到 `i = 11` 时，8 至 11 这个块完整了，尾部为空，这个块和其他块一样参与 top-k 竞争。完整块的条件和尾部规则写在 Eq. 15 和 Eq. 19 里，训练时整条序列虽然都在手上，打分也不会用到未来位置。

预算的数字还能推出一个性质：512 个块加上最多 3 个尾部 token，可见前缀不超过 2,051 个 token 时，每个 query 读到的正好是全部可见 token，和因果全注意力的读取集合相同，从第 2,052 个 token 起才开始跳过低分块。这是本文按 Eq. 16 和 Eq. 19 推出来的。短上下文 benchmark 里有多少位置落在这个范围内，要看每道题的实际长度，报告没有给。即使读取集合相同，QSA 模型和对照的全注意力模型也经过了不同的训练，权重并不相同。

QSA 要分两个阶段训练。第一阶段是 dense distillation，只训练索引器，教师就是全注意力本身：把所有教师头的 softmax 分布相加并做 L1 归一化，得到 query `i` 对每个 token 的概率，再在每个块内取最大值、重新归一化，变成块级目标，用 KL 散度让索引器的块分数去拟合它。这一步训练 1,000 步，学习率 `1e-3`，每步 8 条 256K 序列，共约 2B token。第二阶段是 sparse training，主干按索引器选出的 token 做注意力，和索引器一起训练，KL 只在选中的块上算，教师概率在这些块内重新归一化；8,000 步，学习率 `2.5e-5`，每步 96 条 256K 序列，共约 200B token。（Eq. 17 至 20，PDF 第 6 至 7 页）

同一个块在两处用了不同的池化。索引用的 key 取平均，是对四个 token 内容的概括；教师目标取最大值，只要块里有一个 token 被全注意力重点关注，这个块的目标就高，不会被另外三个 token 平均下去，报告的理由正是保留显著的 token 级信号。训练过程中，带 QSA 和不带 QSA 的 LM loss 曲线几乎重合，报告说两者相差在 `10⁻⁴` 量级，插图里 QSA 略高一点。（Figure 4，PDF 第 7 页）

块大小和索引头数是用长上下文检索定的。消融在 35B-A3B 规模上做，用最长到 1M 的 RULER 打分，模型都完成了第二阶段训练。（PDF 第 8 至 9 页）

左图里块越大，索引越省，横轴的估算相对延迟正好是 `1/r`。下面的分数是本文从 PDF 矢量图坐标读出的近似值，报告没有列出原始数字。`r = 4` 的 RULER 约 86.8，全注意力基线约 86.3；`r = 8` 降到约 83.6，`r = 16` 约 79.4；`r = 2` 和 `r = 4` 持平，估算开销却是两倍。对照方法 IndexShare 让相邻的全注意力层共用同一组 top-k 下标，估算开销为 0.5 时，也就是两个隔着三层 GDN 的注意力层共用一组下标，约 85.5，仍低于基线。作者的解释是，混合结构里相邻注意力层之间的相似度低，跨层共用下标效果受限，层内压缩更合适。

QSA 省下多少，要先看 Figure 6 测的是什么。它是 kernel 级的注意力模块延迟，包含索引器和稀疏核心注意力，对照是 FlashInfer 的 paged GQA 全注意力。prefill 测的是 chunked prefill 下最后一个 16K chunk，batch size 1；decode 是 batch size 4、`next_n = 4`，即带三个 MTP 预测步。报告没有写测试用的硬件。（Figure 6，PDF 第 9 页）

总上下文为 1M 时，注意力模块在 prefill 快 7.6 倍，decode 快 4.9 倍；64K 时两者差不多，上下文越长差距越大。prefill 的 7.6 倍是总上下文为 1M 时处理最后一个 16K chunk 的耗时之比。同一段长输入里靠前的 chunk 前文短，倍数也小，整段 prefill 的加速比会低于这个数。

把 (a) 和 (c) 放在一起看，能看出剩下的开销在哪里。下面同样是从矢量图读出的近似值。总上下文 1M、处理最后一个 16K chunk 时，GQA 约 193 ms，QSA 约 25 ms，其中压缩比为 4 的索引器单独就约 15 ms；decode 时 GQA 约 1.18 ms，QSA 约 0.24 ms，索引器约 0.16 ms。64K 时，prefill 的索引器只占 QSA 约 10.3 ms 中的 1.6 ms。上下文每翻一倍，索引器时间涨到原来的 1.6 到 2.1 倍，越长越接近翻倍；QSA 减去索引器的部分只从约 8.7 ms 涨到约 10.5 ms，因为每个 query 读的 token 数固定在两千出头。

所以到了 1M，QSA 的开销大半在索引器。它仍要给每个完整块打分，单个 query 的工作量随 `n/4` 增长，整段 prefill 是 `O(n²/r)`，压缩只把平方项的常数缩小到四分之一，没有把它变成线性。(a)(b) 里压缩比 4 相对压缩比 1 快 3.8 倍和 4.4 倍，也和这个比例相符。

2,048 的预算限制的是每个 query 这一步读多少，不是保留多少历史。任何一个完整块以后都可能被别的 query 选中，所有原始 token 的 K/V 都得能访问到，选择预算本身不会把 KV 历史截短到 2,048 个 token。这些缓存放在哪里、占多少字节，报告没有给。

这组数字只覆盖注意力模块。48 层里只有 12 层是 QSA，GDN 层、MoE、GR 读写、n-gram 查表和通信都不在对比里，报告也没有给端到端的 prefill 或 decode 吞吐。可以用两个假设感受一下差距：假设某个服务 prefill 时间的一半花在这些注意力层上（`f = 0.5`），再假设这部分整体都按 7.6 倍加速，整体也只快 `1 / (0.5 + 0.5 / 7.6) ≈ 1.77` 倍。这两个条件都是本文假设的，Figure 6 只测了固定位置上的一个 chunk。

## 残差流加宽以后，表达能力花在读上

Transformer 的每个子层都从同一条残差流读输入，再把输出加回这条流。pre-norm（先归一化再进子层）让大模型训练得稳，代价是每个子层读到的都是之前所有子层输出的总和，早期写进去的特征要和后来写入的一切挤在一起。（§2.2，PDF 第 10 页）

第一步只加宽。把残差状态换成 4 条并行分支，每个 block 用 4 个可学习的标量对 4 条分支加权求和作为输入，输出按层号轮流写进其中一条，这是简化版的 AltUp（Eq. 21 至 22）。每个 block 只多 4 个参数，没有矩阵乘法，计算几乎不变，多出来的是搬运 4 条分支而不是 1 条的内存流量。在 400B token 训练的 25B-A3B MoE 上，单是这样就把训练 loss 降了约 0.01。剩下的问题是，在加宽的流上再加多少读写机制才划算。

Hyper-Connections（HC）把读写拆成三个算子：读算子 `H_mix` 决定从各分支取多少组成子层输入，写算子 `H_combine` 决定子层输出按什么比例写进各分支，混合算子 `H_res` 是一个 4×4 矩阵，在恒等路径上直接交换各分支的内容（Eq. 23 至 25）。每个算子都有 static 和 dynamic 两种：static 是训练出来的参数，对所有 token 都一样；dynamic 由当前 token 的残差状态算出来，每个 token 不同。mHC 用 sigmoid 做激活，并把 `H_res` 约束成双随机矩阵。Table 5 记录了从 static 算子出发、逐步加机制这条路的两端（25B-A3B MoE，560B token，评测与 Table 1 相同）：

| 残差设计 | Loss | 9 项平均 |
| --- | ---: | ---: |
| Pre-norm（单条残差流） | 1.617 | 50.91 |
| mHC（static） | 1.596 | 52.49 |
| mHC（dynamic） | 1.594 | 54.47 |
| GR | 1.590 | 54.66 |

数据来源：原报告 Table 5，PDF 第 11 页；只列 Loss 和平均分，各项分数见原表。

从 pre-norm 到 static 算子，loss 降了 0.021，平均分涨 1.58；从 static 到 dynamic，loss 只再降 0.002，平均分却涨了 1.98。两步在 loss 上的大小关系，到 benchmark 上反了过来，只看 loss 会低估第二步。作者说，正是这类情况让他们在整个设计过程中坚持 loss 和 benchmark 一起看。

其余几条结论，报告只给了文字。读的粒度比写的粒度重要：读算子从每条分支一个标量细化到每条分支每个通道一个权重有帮助，写算子同样细化几乎没用，所以写入保持每条分支一个标量。算子要从全部分支预测，比只看最后一条或先把分支池化好，对每条分支分别做 RMSNorm 还有额外收益。读写都足够灵活之后，再加 4×4 的 `H_res` 没有显著改善。（PDF 第 10 至 11 页）

最后定下的 Gated Residual（GR）把表达能力几乎都花在了读上。它和团队在另一项工作中提出的 GatedNorm 是同一个形式，在 RMSNorm 之后接一个轻量的逐元素自门控（Eq. 29）。读的时候，4 条分支先各自做 RMSNorm，再拼起来经过一个秩为 `d/8` 的低秩瓶颈（`d` 是隐藏维度）和 sigmoid，给每条分支的每个通道各出一个门控值，门控后的 4 条分支取平均，作为子层输入。写的时候，每条分支只得到一个标量 `s_i = 2σ(·)`，取值在 0 到 2 之间，子层输出乘上它加回这条分支。注意力子层和 MLP 子层各有一个 GR 模块。

```math
\begin{aligned}
\hat R_i&=\operatorname{RMSNorm}(R_i),\quad i=1,\ldots,4\\
G&=\sigma\Bigl(W_u\operatorname{SiLU}\bigl(\\
&\qquad W_d[\hat R_1;\ldots;\hat R_4]/4\bigr)\Bigr)\\
x&=\frac14\sum_i G_i\odot\hat R_i\\
y&=F(x)\\
s&=2\sigma\bigl(W_w[\hat R_1;\ldots;\hat R_4]/4\bigr)\\
R_i'&=R_i+s_i y
\end{aligned}
```

每条分支各自归一化；$$G$$ 给出 $$4\times d$$ 个门控值，$$x$$ 是子层输入。$$F$$ 可以是 GDN、QSA 或 MoE；$$s$$ 给出 4 个标量，输出写回尚未归一化的各分支。

<TechGraph src="/images/posts/qwen38-flash-next/gr-read-write.svg" title="RICH READ, SCALAR WRITE" alt="GR 的一次读写。四条残差分支各自做 RMSNorm，从全部分支算出 4 乘 d 个逐元素门控值，门控后的归一化分支取平均得到子层输入；子层 GDN、QSA 或 MoE 的输出乘以每条分支一个标量后加回未归一化的四条分支。恒等路径上的 4 乘 4 混合矩阵 H_res 被去掉，分支之间仍经由读、子层和写交换信息；残差分支以 FP8 存储，读和写各融合为一个 kernel。" caption="图解：GR 的一次读和一次写（博主自绘，基于原报告 §2.2 Eq. 30 至 34）。读按分支和通道逐元素加门控，写只有每条分支一个标量；没有显式的分支混合矩阵，交换信息要经过读、子层和写。" />

因为读的时候已经归一化并加了门控，GR 直接取代子层前面的 pre-norm，加宽没有多出归一化层。没有 `H_res`，恒等路径上就没有显式的分支混合：分支之间交换信息，都要经过一次读、一个子层和一次写。每条分支因此就是之前各子层输出按写入标量累加的结果，信息怎么流动很好追踪，后面的分析就用到了这一点。

GR 和 mHC（dynamic）的区别主要在逐元素的读和去掉了 `H_res`，两者在这个规模上质量相当（平均 54.66 对 54.47）。去掉 `H_res` 的好处在 decode：每个 block 少一次对整个残差状态的读取，报告说加宽残差流的推理开销主要就是这类内存流量。作者还认为，GatedNorm 本身改善训练稳定性，去掉需要额外约束的 `H_res` 也少了一个不稳定的来源，前一点在后面的压力测试里有证据。（PDF 第 12 页）

报告也拿另一类做法 Attention Residual（AttnRes）比过：每个子层用 softmax 注意力，在之前各层的输出上决定读什么。28 层模型上，看之前每个子层输出的 Full AttnRes 是 loss 1.762，和 GR 相同；把子层分组汇总的 Block AttnRes 差 0.008 至 0.011；加上 GatedNorm 之后，每种 AttnRes 都再降 0.004 至 0.005，Full AttnRes 加 GatedNorm 到 1.758，比 GR 还低 0.004。（Table 6，PDF 第 12 页）为什么最后不选它，报告没有解释。从机制上看，Full AttnRes 的每个子层都要读之前所有子层的输出，decode 时要搬的数据比读 4 条分支多得多，这可能是原因之一，但这只是本文的推测，没有对应的测量。作者从这组结果得出的是另一点：子层读的输入越复杂，门控帮得越多，GR 的读里带的正是这个门控。

回到开头那个被放弃的捷径。为了少搬字节，团队找过两个办法。第一个就是每个 block 只用门控值最高的两条分支，预训练指标几乎不受影响，后训练后质量明显下降，没有采用；报告在这里时而称它为稀疏读、时而称为稀疏写，说的是同一个变体。第二个是把残差状态存成 FP8。报告给的理由是，GR、门控注意力和 GDN 的门都限制了写进残差流的数值大小，残差值落在较窄的范围里，适合低精度格式。和 BF16 相比，FP8 让残差状态搬运的字节数减半，报告说质量几乎没有损失，这一项采用了，但没有说明这个判断来自哪个阶段的评测。读（Eq. 30 至 32）和写（Eq. 33 至 34）也各自融合成一个 kernel，组 RMSNorm 并进读里，每个 block 在两个方向上各遍历一次加宽的流。（PDF 第 14 页）

加宽出来的容量用在了哪里，报告做了一个分解。没有分支混合矩阵，某个子层读到的输入就能精确拆成来自之前每个子层的贡献向量之和（Eq. 35 至 36）。作者用 Eq. 37 的份额 `π_uv` 衡量路径强弱：子层 v 的输入里，来自子层 u 的那份贡献向量的范数，除以所有来源贡献范数之和。份额衡量的是贡献向量的大小，不是信息量。作者在一个 20 层的 MoE 上，把 GR 模型和配方、数据、优化器、训练步数都相同但没有 GR 的参照模型放在同样的 token 上比较，看每条路径的份额多了多少。

<Figure src="/images/posts/qwen38-flash-next/figure-7-gr-paths.png" alt="原报告 Figure 7。四行分别对应残差分支 b0 到 b3，弧线从写入的子层连到之后读取它的子层，线宽表示相对单条残差流多出的输入份额。b0 上的长弧从第 0 层连到第 11、15、19 层的注意力层，其余分支多是短程连接，灰色竖条标出 softmax 注意力层。" caption="来源：原报告 Figure 7，PDF 第 13 页；仅作忠实裁剪。图中只画出 780 对路径里份额增加不少于 0.05 的 21 条。" />

结果是一条分支专门承担长程路径，另外三条留在局部。这里的长程指跨过很多层，是网络深度方向上的距离，不是 token 位置上的远近。图里 b0 上的路径全部从第 0 层出发，落在第 10 层以后的注意力层。5 个 GR checkpoint 各自都恰好有一条这样的分支，典型跨度 10.9 层，其余分支是 3.4 至 3.9 层。第 0 层 GDN 到第 15 层注意力的份额，从参照模型的 0.020 升到 0.138。读这些分支最多的是 softmax 注意力层，作者据此认为全局注意力是枢纽，负责整合被 GDN 压缩掉的显式长程历史。所有路径按份额加权的平均跨度几乎不变（3.97 对 3.91），变的是份额在不同跨度之间的分布，集中到了少数几条路径上。（PDF 第 12 至 14 页）

这是对训练好的模型做的观察性分解，说明了 GR 的读权重集中在哪里。报告没有做干预实验，比如关掉那条长程分支、看 loss 和 benchmark 怎么变，所以这张图推不出前面的收益里有多少来自这些路径。

## 查表容量：loss 一直在降，benchmark 先停了

n-gram embedding 是在主干之外加容量的办法：以每个 token 结尾的几个短 n-gram 作为键去查 embedding 表，查到的向量加强这个 token 的表示。查表地址只由 token 序列决定，算这个 token 之前就能知道要取哪些行，所以表可以放在主机内存里，提前异步取回；每个 token 多出来的计算可以忽略。（§2.3，PDF 第 14 至 15 页）报告没有公开用了哪几阶 n-gram、地址怎样映射到表槽、向量维度和存储精度。这一节的实验都按每个激活参数 300 个训练 token 的比例训练，模型规模没有写明。

放在哪一层，是在 n-gram 参数总量固定的前提下比的（Table 7，PDF 第 14 页）。没有 n-gram 的基线 loss 1.585、9 项平均 45.44；放在第 2 层时 loss 1.541、平均 47.94。第 1、2 层表现较强，中间层和深层也差得不多，没有哪个深度一直占优。把同样的参数分到两层也没有稳定的好处，第 2 层加第 25 层的 loss 略低（1.540），下游并没有更好。最后只用一层，放在第 2 层，理由是工程上的：取表可以和第 1 层的计算重叠。

表该多大，报告分成两个问题来测。第一个是固定总参数：加 n-gram 表的同时减少 MoE 专家，总参数不变（Table 8，PDF 第 15 页）。loss 随表的大小不单调，在 n-gram 词表为基础词表 10 倍、表占总参数 25% 时最低，和前人报告的最佳分配点一致；可是域外的 uncheatable PPL 几乎不动，下游 benchmark 也没有明显好过只有 MoE 的基线。作者由此认为，n-gram 表和 MoE 专家在扩容量时扮演的角色不同，后面的实验改为保持 MoE 不变、额外加表。

loss 一路单调下降，到 200 倍是 1.526。下游 benchmark 从无到有时普遍上涨，之后多数项饱和或来回波动：MMLU 在 50 倍以后基本不动，GSM8K 和 MATH 都在 20 倍时最高，之后反而回落。中文的 C-Eval 和 CMMLU 是例外，一直随词表变大而上涨。报告还试过几种提高参数效率的办法，包括压缩词表的 token 归一化、给各阶 n-gram 分配不同的槽数、按频率划分槽位，在他们的配方里都没有稳定的收益。（PDF 第 15 页）

Flash-Next 最后带了 51B 参数的表，对应哪个词表倍数，报告没有写。表放到主机内存里，加速器上不占这部分容量，代价并没有消失。按每个参数 2 字节估算（BF16 是本文的假设，原文没有写存储精度），51B 参数约 102 GB，要在主机内存里放下；每个 token 查到的行要经过主机到加速器的链路，第 1 层算完时还没取回，第 2 层就得等。传输量、带宽占用和等待时间，都没有测量数据。

## Muon 只用在充当线性映射的矩阵上

结构定下来，优化器也得跟着调整。Flash-Next 的主优化器是 Muon。AdamW 对每个参数元素各自做自适应缩放；Muon 把一个权重矩阵的动量当成整体，用 Newton-Schulz（NS）迭代把它近似正交化，再作为更新方向。报告的设置是：对动量系数 0.95 的 Nesterov 动量做正交化，NS 迭代 8 步，每步系数用 Polar Express 方法给出的、在给定步数下最坏误差最小的那一组，结果乘上 `0.2 · sqrt(max(A, B))`，让不同形状 `A × B` 的矩阵的更新 RMS 不随形状变化。8 步比更少的步数正交化得更准，作者说这在压力测试中减少了梯度范数尖峰的幅度和频率，为了这点稳定性多付了一些计算。（§3.1，PDF 第 16 页；Introduction，PDF 第 2 页）

哪些参数用 Muon，是这份配方按实验定下的规则。注意力的 q/k/v 和输出投影、GDN 的输入输出投影、路由专家和共享专家的 fc1/fc2、n-gram 层的 key/value 投影用 Muon，这些都是充当线性映射的二维权重。例外和报告给的理由如下。

| 参数 | 优化器 | 报告给的理由 |
| --- | --- | --- |
| MoE 路由器 | AdamW | 训练早期用 Muon 会放大波动、让路由不稳，中后期换成 Muon 不出问题，也没有收益。作者推测路由的每个输出维度是一个专家的分数，维度之间基本独立，没有可供正交化利用的共享线性结构 |
| GR 的两个低秩投影 | AdamW | 形状非常扁长，AdamW 效果更好 |
| GDN 的衰减和 β 投影 | AdamW | 每个头只出一个标量，实际是向量，正交化没有意义 |
| 注意力输出门、GDN 的 z 投影 | AdamW | 消融中 AdamW 持平或略好 |
| n-gram embedding 表 | Adam，关闭 weight decay | 没有单独说明；引言笼统写作 AdamW，这里以 §3.1 为准 |

数据来源：原报告 §3.1，PDF 第 16 页。输入 embedding 和输出头也留在 AdamW，引言把这几类概括为正交化不现实或没有帮助。

Megatron-LM 里，注意力的 qkv 投影、SwiGLU 的 fc1 和 GDN 的输入投影各自存成一个拼接的大矩阵，语义上却是沿输出维度拼起来的几个独立线性算子。直接对拼接矩阵做正交化会错在两处：迭代会把互不相关的子块之间的奇异方向混在一起，缩放系数也按拼接后的形状而不是真实算子的形状计算。所以要先把融合的梯度切开，各自做 NS，再拼回原来的布局。qkv 和 GDN 输入投影按头切分，loss 和 benchmark 都有改善；fc1 切成 gate 和 up 两半，loss 基本不变，benchmark 略有提高。切开之后，GDN 衰减投影这样的子矩阵也能单独排除在 Muon 之外。（PDF 第 16 页）

Muon 还带来了 AdamW 没有的工程问题。对 `A × B` 的矩阵做 K 步 NS，约需 `4K · max(A, B) · min(A, B)²` FLOPs，取决于形状而不只是元素个数。举个算例（形状是本文假设的）：4096×4096 和 1024×16384 两个矩阵都是约 1,680 万个元素，按 K = 8 算，前者约 `2.2 × 10¹²` FLOPs，后者约 `5.5 × 10¹¹` FLOPs，差 4 倍。NS 迭代又必须拿到完整矩阵。张量并行（TP）下没有哪张卡持有完整的权重；数据并行（DP）下，Megatron 按元素个数平均切分，分到大方阵的卡就会拖慢所有人。团队为此开发了 Canzona，按估算的 NS FLOPs 把整个矩阵分配给各个 DP rank（不在张量内部切开），再在 TP rank 之间重组出完整矩阵，每个持有者做的更新在数学上等同于单卡 Muon。另外，切开融合矩阵后一层就有上百个子矩阵，优化器的一步变成一长串很小的 kernel，耗时由启动开销决定，于是整个优化器步用 CUDA graph 捕获。（PDF 第 16 页）

## 先在压力下证明更稳

规模到万亿参数、数十万亿 token 时，会出现小规模实验里看不到的不稳定。比如长时间待在峰值学习率附近，给不稳定更多冒头的机会，表现为 loss 尖峰甚至发散，只能退回 checkpoint 重来。（§3.3，PDF 第 19 页）Flash-Next 同时改了残差、token mixer 和优化器，三者都改变了更新和激活的缩放方式，长时间训练下还稳不稳，得先验证。

压力测试借用了一个观察：调高学习率，小模型上也能复现大规模训练的不稳定（Wortsman et al.）。具体做法是把学习率固定在最优值的 2 倍或 4 倍，不做衰减，模拟生产训练长时间停在峰值学习率的状态。测试对象是 28 层的 25B-A3B MoE，所有 run 用相同的 batch size 和 0.5 的梯度范数裁剪阈值。通过的标准是新配方至少要和已经成功扩展过的 Qwen3.5 结构加 AdamW 一样稳。记录三个量：loss 尖峰，即某一步的 loss 比 201 步滚动中位数高出 0.1 以上；裁剪前梯度范数的 p99.9 和越过裁剪阈值的次数；每个 block 的最大激活值。（PDF 第 20 页）

<Figure src="/images/posts/qwen38-flash-next/figure-10-stress-loss.png" alt="原报告 Figure 10。左图学习率固定为最优值的 2 倍，右图为 4 倍，比较 AdamW 加 Qwen3.5 结构、Muon 加 Qwen3.5 结构、Muon 加 Gated Residual 三条训练 loss 曲线；4 倍时 AdamW 曲线出现多次尖峰和一次大幅跳升。" caption="来源：原报告 Figure 10，PDF 第 19 页；仅作忠实裁剪。粗线是滑动平均，背后的浅色线是逐步的 loss。" />

2 倍学习率时，AdamW 基线开始出现尖峰，每 1 万步 4.3 次，两个 Muon 配置都是 0.2 次。到 4 倍，AdamW 每 1 万步 183 次尖峰，19,932 步里有 213 步越过裁剪阈值，约占 1.1%。两个 Muon run 都没有越过裁剪阈值；loss 尖峰方面，带 GR 的 run 记录为零，只用 Muon 的那个，报告没有给 4 倍时的次数。（PDF 第 20 页）

梯度和激活的曲线（Figure 11）里，2 倍学习率下，Muon run 的梯度范数中位数和最大激活值都比 AdamW 大，尖峰却少得多。至少在这组曲线里，激活值大不等于尖峰多。加上 GR 之后，梯度范数尖峰的频率和幅度、激活离群值的大小都降了下来。（PDF 第 20 至 21 页）

这组对比里，从 AdamW 到 Muon 换的是优化器，从 Muon 到 Muon + GR 加宽和门控是一起加的。为了把门控单独拎出来，报告又做了一组单变量对照：同样是 28 层模型，学习率固定在最优值的 3 倍，优化器保持 AdamW，结构和数据顺序都不变，只开关 GatedNorm（Figure 12）。打开门控后，每 1 万步的尖峰从 32.0 次降到 3.2 次，越过裁剪阈值的次数从 256 降到 20。不带门控的基线在 1 倍、2 倍、3 倍学习率下，激活离群值几乎和学习率成正比地变大，尖峰频率则涨得快得多；带门控、用最高学习率的 run，离群值反而比不带门控、用最低学习率的还低。（PDF 第 20 至 21 页）这组隔离是在 AdamW 下做的，门控在 Muon 下单独起多大作用，没有对应的单变量实验。

作者的解释是，用高学习率训练需要某种重新缩放的机制：没有显式的门，网络就靠长出激活离群值来完成这种缩放，于是变得脆弱；乘性的门直接提供了缩放，训练就稳住了。这个解释引自团队此前关于门控注意力和离群值的工作，是对这些曲线的解读，这组实验本身没有直接证明它。

压力测试是故意偏离生产配置的。为了确认好处在真实配置下还在，报告比较了三个 run 的前 276B token：Qwen3.5 结构加 Muon、同样的结构再加 GR、完整的 Flash-Next 配方（GR 进一步细化，并加上 n-gram 层）。三者的数据顺序、学习率计划和优化器相同，学习率就是最终训练用的值。（PDF 第 21 至 22 页）

<Figure src="/images/posts/qwen38-flash-next/figure-13-production-early.png" alt="原报告 Figure 13，三个 run 前 276B token 的曲线：(a) 训练 loss，带最后 126B token 的放大插图；(b) 裁剪前梯度范数，插图为 1000 步窗口内的标准差；(c) 残差激活最大值。浅灰色区域是学习率 warmup。" caption="来源：原报告 Figure 13，PDF 第 21 页；仅作忠实裁剪。阴影带是学习率 warmup。" />

到 276B token 时，加 GR 让 loss 降了 0.026，完整配方又降了 0.032，比 Muon 基线合计低 0.058。梯度范数方面，只用 Muon 的 run 中位数约是两个带门控 run 的两倍，p99.9 是它们的 4.2 倍以上（0.097 与 0.298，对比 0.053 与 0.071、0.043 与 0.066），也是唯一越过裁剪阈值的 run；两个带门控的 run 在 1000 步窗口内的梯度范数标准差低 4.3 至 4.7 倍。作者说这在 8 倍于压力测试的模型规模、生产学习率下复现了压力测试的结论，但没有说明 8 倍按什么口径算。完整配方的梯度范数比 Muon + GR 还低，作者推测主要是因为把输出前的残差读取和最后的归一化融合成了一次门控读取。残差激活最大值上，加 GR 让各个深度的最大值都明显下降；从图上看，完整配方的最大值介于另外两个 run 之间。

报告还说，靠这些稳定性改进，Flash-Next 的完整规模训练全程没有出现一次 loss 尖峰或梯度范数异常波动，也没有依赖 qk-clip、SwiGLU-clip 这类显式裁剪。（PDF 第 3、22 页）这两种是专门压注意力 logits 或激活的手段，和常规的全局梯度范数裁剪不是一回事，后者仍然配着，Figure 13 里只用 Muon 的 run 就越过过它。报告展示的生产曲线只到前 276B token，全程无尖峰这一句是作者的陈述。

## 更稳以后，学习率和 batch size 也得重新找

结构和优化器都变了，上一代用 scaling law 拟合出的学习率 η 和 batch size B 未必还是最优。团队用 Qwen3.5 的超参数配方训练新结构时，发现训练明显比以前稳，也就是上一节的结果，觉得还有空间用更激进的设置，于是重新拟合了超参数的 scaling law。新的拟合预测出明显更大的 batch size 和学习率，学习率随模型变大衰减得也更慢。报告说更大的 batch 提高大规模训练的并行吞吐，更大的学习率改善收敛。（§3.2，PDF 第 3、16 至 17 页）

小规模拟合的 scaling law 只有外推得准才有用。报告把两个预测分开验证，各放在最容易暴露错误的设置里：batch size 在小模型、长训练上验证，batch 过大的坏处在 token 很多时才显出来；学习率在大模型、短训练上验证，那里最大的风险是训练不稳。

batch size 用 20 层的 10.8B-A0.89B MoE，训练 4T token。比较旧配方的 B = 12.6M、新预测的 25.2M 和再大 1.5 倍的 37.7M，每个 batch 配上 scaling law 给它的学习率，token 总量相同。最后 20B token 的平均 loss 分别是 1.5774、1.5702 和 1.5707：新预测比旧配方好 `7.2 × 10⁻³`，再大 1.5 倍只差 `4.3 × 10⁻⁴`，作者认为不显著。比预测值小的一侧 loss 涨得很陡，比它大的一侧基本平坦。（Figure 8a，PDF 第 17 页）

大规模训练常在前期逐步加大 batch size，即 batch-size warmup。理由是训练早期的临界 batch size 较小，大 batch 效率低，小 batch 配合缩放过的学习率也更容易在头几步稳住。团队之前的超参数扫描显示，用 Muon 时把 batch 调到预测值以下的惩罚比调大更重，Muon 在 AdamW 已经开始退化的大 batch 下仍能保持数据效率；对稀疏 MoE，大 batch 还能让每个专家每一步都分到足够多样的 token。于是他们重新测了 batch-size warmup：从 6.3M 开始，每次加 6.3M，到 524B token 时达到 25.2M。一个变体保持恒定 batch 时的最优峰值学习率，另一个变体降低峰值学习率，照顾前期的小 batch。（PDF 第 17 至 18 页）

两个变体都没带来好处，都落在 run 间波动范围内，但都比恒定 batch 略差，分别差 `2.5 × 10⁻⁴` 和 `3.5 × 10⁻⁴`。相同 token 预算下，warmup 要多走 18.8% 的优化器步，报告说这意味着更多墙钟时间，但没有给时间数字。对 Muon 来说，每一步都要对所有矩阵做一遍 NS，这部分开销和 batch 大小无关，步数多了它也跟着多，这是本文结合 §3.1 的推论。这一组 run 都没有出现不稳：没有哪一步的 loss 比局部中位数高出 0.1 以上，裁剪前梯度范数的 p99.9 在 0.088 至 0.190 之间，远低于 0.5 的阈值。

作者从曲线读出的过程是：warmup 期间 batch 小、梯度噪声大，loss 更高；batch 到位后，warmup 版本因为前期多走了步数，短暂领先；随着学习率衰减、模型接近收敛，这点步数优势被抹平，恒定 batch 最后胜出。所以生产训练不用 batch-size warmup。去掉的只是 batch size 的 warmup，学习率 warmup 仍然保留，Figure 9b 和 Figure 13 里都画着 warmup 的阴影区间。

学习率在 48 层的 156B-A7B MoE 上验证，训练 419B token。比较的设置是预测最优值（B = 8.4M，η = `1.76 × 10⁻³`）、学习率除以和乘以 √2、batch 加大 25% 并配上相应的学习率，以及上一代配方（B = 4.2M，η = `6.8 × 10⁻⁴`）。旧配方最后的 loss 比预测最优值高 `7.8 × 10⁻³`；预测最优值附近的四个设置彼此相差在 `7 × 10⁻⁴` 以内，接近噪声水平，batch 大 25% 的那个名义上最好，好 `3 × 10⁻⁴`。（Figure 9，PDF 第 18 页）下游 benchmark 如下。

数据来源：原报告 Table 10，PDF 第 19 页；只列平均分，各项分数见原表。

预测最优值的平均分最高，旧配方落后约 4.1 分，往大学习率或大 batch 偏一点只掉零点几分。作者自己说明，每个 run 只评测了一次，前几名之间差距很窄，这些排名应当作为观察，差别可能都在评测噪声之内。稳定性上，五个 run 在 warmup 之后都没有触发过梯度裁剪；预测最优值下裁剪前梯度范数的最大值只到阈值的 28%，旧配方因为 batch 小、梯度更嘈杂，到了 51%；学习率乘 √2 的 run 也一样稳。（PDF 第 18 至 19 页）

报告结论把这几步串成一条因果链：GR 提供重新缩放，改善了训练稳定性，稳定性的余量又把最优学习率和 batch size 往上推，同时改善吞吐和收敛。（§5，PDF 第 23 页）这几组实验能支持的是，新结构加 Muon 这个组合的最优点确实更大，在验证设置下按预测值训练也更好。重新拟合针对的是整套新配方，没有分别测 GR 或 Muon 各自让最优点移动了多少；报告在讨论 batch size 时，也把一部分原因归于 Muon 在大 batch 下的数据效率和 MoE 专家需要足够的 token 信号。稳定性余量推高最优超参数这一环，是作者对几组实验的综合判断，没有被单独测过。

## 最终对比能证明什么，还缺什么

Table 11 把 Flash-Next-Base 和两个 Base 模型放在一起：它在全部 14 项上都高于 dense 的 Qwen3.8-27B-Base。对 Qwen3.7-Plus-Base 落后的 6 项是 MultiPL-E（79.09 对 81.68，差 2.59）、MATH（72.78 对 74.38，差 1.60）、MMLU-Redux（差 0.79）、INCLUDE（差 0.50）、GPQA（差 0.10）和 MMLU（差 0.07）；领先最多的是 MGSM（多 3.91）和 SuperGPQA（多 2.94）。这些都是 Base 模型在 few-shot 或 zero-shot 设置下的成绩，每项的 shot 数见报告 §4。（PDF 第 22 至 23 页）

这些数字只覆盖预训练阶段。报告第 1 节说后面会评测 Base 模型和后训练模型，正文里只有 Base 模型的结果。报告说结构改进加上小得多的激活参数让推理成本显著降低，可除了 Figure 6 的 kernel 级测量，没有给端到端的吞吐、延迟或成本。各节的消融也在不同规模和 token 预算下完成：GR 消融在 25B-A3B，QSA 消融在 35B-A3B，batch size 验证在 10.8B-A0.89B，学习率验证在 156B-A7B。这些增益不能相加，也拆不出最终成绩里每个部件各贡献了多少。

作者在结论里点名的最大瓶颈是评测吞吐：要是有一种更便宜的中等规模探针，能可靠地预测后训练之后的排序，设计空间就好搜得多。（§5，PDF 第 23 页）开头那个只用两份状态的捷径，和全注意力层去掉 RoPE 的 NoPE，在预训练 loss 和 benchmark 上都看不出问题，做完后训练才暴露。只在预训练阶段验证，这类问题就会漏过去，能提前预测它们的便宜办法目前还没有。
