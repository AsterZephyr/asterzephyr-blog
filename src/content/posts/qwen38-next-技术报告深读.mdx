> 下文页码均指上述 PDF。对象是 **Qwen3.8-Flash-Next**。

假设你在筛选下一代模型架构。方案 A 的训练 loss 明显更低，方案 B 的 loss 只改善了一点，但实际任务做得更好；方案 C 在预训练时与原模型几乎没有差别，完成后训练后却开始退化。只盯训练曲线，你可能选中 A、忽略 B，又把 C 当成一次免费的优化。

Qwen3.8-Next 技术报告把这些不整齐的结果写了出来。作者围绕注意力、残差连接、N-gram Embedding 和优化器做了多组实验，也交代了哪些节省计算的尝试最终没有采用。沿着对照组和失败案例，可以看清这些设计是怎样选出来的。

下文从目标和成本口径讲起，再看机制与实验。测量结果均来自作者，示意图和工程分析由本文整理，未进行独立训练或推理复现。

## 1. 先把“更省”说清楚

报告给出的模型规模是 **125B 主体参数、每 token 激活 6B 参数，另有 51B 的 N-gram Embedding 表**。最终 Base 模型与上一代 Qwen3.7-Plus-Base（397B-A17B）比较，在 14 项预训练评测中领先 8 项，剩余 6 项的差距不超过约 2.6 个百分点。作者同时报告约三分之一的激活参数和约三分之一的训练 tokens，对应约九分之一的训练 FLOPs。（Abstract；Table 11，p22-23）

理解这组结果，需要分开看四件事。

**总参数量回答存储容量问题。** 激活参数只描述一次 token 计算涉及的参数口径。MoE 没选中的专家仍然需要存放在某处；N-gram 表搬到主机内存，也只是改变了存储位置，没有让这些参数消失。根据报告列出的类别，125B 与额外 51B 相加约为 176B。这个加法能帮助认识容量组成，却不能直接算出某个框架的显存需求。

**激活参数量帮助理解每个 token 的计算负担。** 但它不是完整推理成本模型。专家通信、注意力计算、状态读写、量化格式和批处理方式都会改变实际耗时。即使两个模型的激活参数相近，它们在长上下文下的表现也可能相差很大。

**训练 FLOPs 描述算术工作量。** 三分之一乘三分之一可以帮助理解论文中约九分之一的量级关系，但它不是审计过的美元账单，也不包含所有研究试验。换一种优化器、增加数据搬运或者降低设备利用率，都可能让相同 FLOPs 对应不同的墙钟时间。

**任务成绩描述的是特定评测条件下的能力。** 14 项 Base 评测并不自动覆盖完整 Agent 工作流、视觉任务或各种生产场景。能力是否接近，要结合具体任务和评测方式判断。

这些实验支持了在特定能力目标下显著减少训练计算的设计方案。要据此决定是否部署，还需要测整模型延迟、并发吞吐、主机与设备内存，以及失败任务的分布。

## 2. 沿一次前向计算，找到四种设计的位置

全局结构图中有三类信息流：**跨 token 的历史、跨网络层的特征、局部 token 组合对应的查表向量**。

<Figure src="/images/posts/qwen38-next-技术报告深读/p01.png" alt="Qwen3.8-Flash-Next 架构，含 GDN、QSA、GR、MoE、N-gram 和 MTP" caption="来源：原报告 Figure 1，PDF 第 2 页；仅作忠实裁剪。" />

跨 token 的历史由两种注意力机制处理。多数层使用 **Gated DeltaNet（GDN）**，把已经读过的内容压缩进矩阵状态；每四层安排一层全局注意力，保留直接检索历史 token 的能力。到继续预训练阶段，这些全局注意力层再替换成 **Qwen Sparse Attention（QSA）**，降低长输入的注意力开销。

跨网络层的特征由 **Gated Residual（GR）** 管理。它把一条残差流扩展成四条分支，每个 attention 或 MLP 子层先从分支中读取，再把计算结果写回。这里的跨层指网络深度方向，与 KV cache 保存对话历史的作用不同。

局部 token 组合则进入 **N-gram Embedding**。给定当前 token 及其前面少量 token，模型能够确定查表地址。表放在主机内存中，通过异步预取，把需要的向量送到第 2 层附近。它提供额外容量，也为设备内存与传输调度引入了新问题。

MoE 仍承担子层中的非线性变换。报告并没有因为加入查表记忆而取消专家网络；后面会看到，作者专门比较了“减少专家、增加表容量”和“保持专家、额外增加表容量”，两者的结果并不一样。

MTP 位于输出预测部分。报告还把 MTP 内的注意力改为 QSA，并在多个预测步之间复用索引，以减少草稿计算的重复工作。是否能转化成更高服务吞吐，则还取决于接受长度、验证开销和请求分布。

为了方便理解，可以把模型想成一个处理长材料的研究团队：GDN 保存持续更新的工作记忆，QSA 帮助回查重要原文，GR 让前面步骤得到的特征能够被后面的步骤使用，N-gram 表提供按局部词组定位的辅助资料。这个类比只帮助区分职责；实际的记忆和资料都是训练得到的数值表示，不是可直接阅读的笔记或事实数据库。

## 3. GDN：先检查已经记住什么，再写入修正量

### 3.1 固定大小的状态，换来了怎样的限制

完整 self-attention 的优势是直接按内容访问前面的 token；代价是标准注意力在 prefill 阶段面对二次增长的 token 配对，生成时还要维护不断增长的 KV cache。Sliding-window Attention 把范围限制在局部窗口内，减少计算和缓存，但窗口之外的信息需要通过其他层间接传递。

GDN 选择把历史压进固定形状的状态矩阵。所谓固定大小，是指在模型形状确定后，单个 head 的递推状态不随已经读过的 token 数量线性增长。它不是无限容量：新信息和旧信息共用同一状态，模型必须选择保留、衰减或修正哪些关联。（§2.1.1，p3-5）

因此，全模型没有被替换成纯 GDN。每隔几层保留全局检索，意味着架构同时承认了压缩记忆的效率和限制。日常更新可以依赖紧凑状态，遇到需要细节的计算，则仍有机会回到历史 token。

### 3.2 Delta update 的重点在“误差”

令旧状态为 `S_prev`，当前 key、value、query 分别为 `k`、`v`、`q`。报告 Eq.1-4 的递推可以写成下面四步，转置方向与论文保持一致：

```text
S_decay = α · S_prev
error   = v − transpose(S_decay) · k
S       = S_decay + β · outer(k, error)
y       = transpose(S) · q
```

第一步用衰减门 `α` 控制旧状态的保留程度。第二步先从衰减后的状态读取与当前 key 相关的旧预测，再与当前 value 比较。第三步把差值写回，写入强度由 `β` 控制。最后用当前 query 从更新后的状态读取输出。

这个过程与“每来一个 token，就把一份 key-value 外积堆进去”有实质差别。如果某个关联已经记住得比较准确，新输入造成的修正量就小；如果关联发生变化，更新集中在预测误差上。公式中的减法，决定了它具有针对已有关联进行纠错的能力。

<TechGraph src="/images/posts/qwen38-next-技术报告深读/g02.svg" title="GDN 单步递推" caption="图解：衰减、比较、纠错写入与读取（博主自绘，基于原报告 §2.1.1、Eq.1-5，PDF 第 4 页）。" />

实际模块还包含输入投影、短因果卷积、q/k 的 L2 normalization、输出归一化和输出 gate。短卷积先提供局部信息，归一化约束进入递推的量级。报告采用有界 sigmoid 输出门，并使用 zero-centered RMSNorm，约束状态读出后的数值行为。

### 3.3 对照实验支持混合结构，但不能替代所有归因

Table 1 在 28 层、25B-A3B MoE 模型上比较完整注意力、SWA hybrid 和 GDN hybrid。训练先使用 400B tokens、4K context，再使用 80B tokens、32K context；两种 hybrid 都是每四层保留一层完整注意力，SWA 的局部窗口为 128。

在这组条件下，GDN hybrid 的九项平均分为 53.81，高于完整注意力的 49.87 和 SWA hybrid 的 51.15。它相对完整注意力领先八项，相对 SWA hybrid 领先七项。但 EvalPlus 上并非 GDN 最好。这是选择混合结构的证据，也提醒我们关注具体任务分布。作者明确指出，这一整体架构比较不能单独解释每个局部组件带来了多少提升。（Table 1，p5）

作者还试过在完整注意力层移除 RoPE：预训练阶段看起来差别不大，后训练后却更容易出现无法结束的生成，因此保留了 RoPE。报告没有给出完整量化表，无法计算准确的退化幅度，但这一观察说明，预训练 loss 接近并不足以判断删掉 RoPE 后的输出行为。

## 4. QSA：稀疏注意力还要为索引付多少钱

### 4.1 找重点本身也会消耗计算

稀疏注意力的直觉是：历史很长，每个 query 不必精读所有 token，只计算重要部分。但在真正计算之前，系统还要找到重要部分。如果索引器本身仍逐个比较大量 query 和历史 key，长输入下，筛选工作也会成为开销。

QSA 将索引器的 key 序列压缩成微块，先以块为单位判断重要性，再回到原 token 做核心注意力。沿用前面的类比，就是**用摘要定位，再精读原文**。Figure 3 中，被选中的块最终仍会展开为原始 token。（§2.1.2，p5-7）

### 4.2 四个 token 一组，位置编码放在压缩之后

报告采用压缩比 `r = 4`。相邻四个 token 的 key 先做平均池化，再进行归一化和 Partial RoPE。这里顺序很重要：先压缩内容，再赋予块位置，可以避免把已经带有不同旋转相位的表示直接平均。

索引器采用 MQA，四个 query heads 共用一个 key head。query 保留自己的位置，压缩块使用起始 token 的位置。多头相似度经过 ReLU 后相加，形成块级重要性分数。

给定 token 预算 `K = 2048`，完整块预算是 `ceil(K / r)`，在当前设置下最多选择 512 个块。随后把选中块展开为其原始 token 索引，用这些 token 的 K/V 计算 sparse core attention。

<TechGraph src="/images/posts/qwen38-next-技术报告深读/g03.svg" title="微块索引如何回到原始 token" caption="图解：QSA 的块级选择与 token 级精读（博主自绘，基于原报告 §2.1.2、Eq.12-20，PDF 第 6-7 页）。" />

还要补上一个容易被概念图省略的因果边界。当前 query 只能给已经完整出现的历史块打分。若当前 token 落在一个尚未填满的块内，这个块中已经可见的尾部 token 会直接加入注意力集合。于是“2048 个 token 预算”不能简单写成“最终永远只看 2048 个 token”：当前配置可能另带最多三个可见尾部 token。块级选择不能通过提前读取未出现的 token 偷看未来。

离线完整序列训练时可以拿到一个块里的所有 token，掩码处理不当就可能让训练利用生成阶段不可获得的信息。报告在 Eq.15 和 Eq.19 中明确写出了完整块限制和尾部路径。

### 4.3 模型需要学习适应稀疏选择

QSA 在 256K 序列长度的 continued pretraining 中引入，分为两阶段。

第一阶段只训练索引器。完整注意力给出 token 级分布，跨教师头求和并归一化后，以 max pooling 变成块级目标，再归一化，用 KL divergence 训练索引器。这里教师目标用 max pooling，而索引键的内容压缩用 average pooling，两者职责不同：前者保留块中显著 token 的监督信号，后者生成用于检索的键表示。

第二阶段打开稀疏注意力，让 backbone 与索引器一起适应新的信息选择方式。索引器 KL loss 只在被选中的块上计算，教师概率也在这个集合内重新归一化。两阶段的步数、batch 和学习率如下。

<TechGraph src="/images/posts/qwen38-next-技术报告深读/g04.svg" title="从密集教师到稀疏模型" caption="图解：QSA 两阶段训练（博主自绘，基于原报告 §2.1.2 Training Details，PDF 第 6-7 页）。" />

按报告的 batch 与步数相乘，第一阶段约处理 2B tokens，第二阶段约处理 200B tokens。这个量级说明它并非给已有权重增加一个零成本推理开关。Figure 5 的索引头消融也显示，只完成第一阶段就直接稀疏化会有明显差距，联合训练后才恢复到接近完整注意力的水平。

### 4.4 核心注意力更快，不等于整体服务同比变快

<Figure src="/images/posts/qwen38-next-技术报告深读/p02.png" alt="QSA 索引器及注意力模块在不同上下文长度下的 prefill 和 decode 延迟" caption="来源：原报告 Figure 6，PDF 第 9 页；仅作忠实裁剪。图中为内核级测量。" />

Figure 6 在 1M context 处报告注意力部分 prefill 加速 7.6 倍、decode 加速 4.9 倍。这一测量包含索引器与 sparse core attention；prefill 使用最后一个 16K chunk、batch size 1，decode 使用 batch size 4、`next_n = 4`，其中包含三个额外 MTP 预测步。对照是 FlashInfer 的 paged GQA。

从图里可以得出“这组条件下注意力模块明显更快”，但不能得出“整个模型每秒输出 token 也提高 4.9 倍”。MoE、GR、通信、调度以及其他部分都还在运行。举一个**仅用于解释的假设**：如果某服务原来只有一半时间花在被优化的部分，那么即使这部分快五倍，总时延也只是从 1 降到 `0.5 + 0.5 / 5 = 0.6`，整体约快 1.67 倍。这个数字不是 Qwen 的实测结果，而是解释局部加速如何受到时间占比约束。

复杂度表述也应保留原貌。QSA 把索引器从 `O(n²)` 降为 `O(n²/r)`。当 `r` 固定为 4 时，它降低了常数开销，式子仍然含有二次项。因此不能因为核心注意力变稀疏，就把整个索引过程宣称为严格线性复杂度。

### 4.5 更长的上下文，需要看绝对成功水平

Table 3 给了比“支持 1M”更有判断力的信息。在 8-needle MRCR 的 1M 设置下，QSA 得分 26.44，完整注意力为 20.71；在 512K 下则为 40.53 对 30.66。QSA 在这些测试中表现更好，但绝对分数仍然提醒读者：能接受很长的输入，不代表在所有困难检索任务中都能可靠使用这些内容。

RULER 的得分明显更高，也不矛盾。不同评测要求不同，单一窗口长度无法代替任务能力描述。对于需要跨大量材料做精确引用的应用，应使用自己的证据定位、错误引用和遗漏率来补充验证。（Table 3，p8；以上应用检查为本文建议）

MTP 实验则检查另一件事：复用 QSA 索引是否改变草稿接受长度。四步 speculative decoding 下，Table 4 平均接受长度为 4.07，对照为 4.06。它支持“在所测任务中接受长度基本保持”的判断，尚不能单独证明完整投机解码系统的加速比。

## 5. Gated Residual：更宽的残差流，怎样变成有效通路

### 5.1 深度增加以后，早期特征怎样被继续使用

普通残差连接可以简单写成 `R_next = R + F(Norm(R))`。每个子层读取同一条流，再向其中加入自己的输出。这给梯度和特征提供直接路径，但随着越来越多的层写入，早期信息也需要与后来加入的内容共存。

扩大残差流的基本想法，是让网络保存多条分支。仍然用前面的研究团队类比：原来所有中间结果都挤在同一份工作记录里，现在允许存在几份并行记录。但只是多放几份记录还不够，后续步骤怎样读取它们、怎样把新结果写回，才决定额外空间是否真的有用。

报告先试验了一个很简化的宽残差：用可学习标量对分支求和，子层输出按深度轮流写到一条分支。这样几乎不引入额外矩阵乘法，就能改善训练 loss。随后的问题是，要在这个基础上增加多少读写机制才划算。（§2.2，p10）

### 5.2 读、写与分支混合，是三个不同操作

Hyper-Connections 一类设计把操作分成三部分：`H_mix` 决定子层从分支中读什么，`H_combine` 决定子层结果怎样写回，`H_res` 则直接在残差分支间进行混合。

Qwen 的实验结论是，额外表达能力应该更多放在“读”上。让读取权重依赖当前残差状态有帮助；进一步从每分支一个标量细化到每分支、每通道一个权重，也有帮助。相同细化用于写入，收益很小，因此保留每分支一个写入标量。读写足够灵活以后，额外的 `H_res` 分支混合没有带来明显改善，最终被删除。

消融后的读写操作并不对称：读取更细，写入更简单，分支混合带来的额外内存访问也被省掉了。

Table 5 很能说明为什么不能只看 loss。Pre-norm 到静态 mHC，loss 从 1.617 降到 1.596，九项平均分从 50.91 升到 52.49；静态到动态 mHC，loss 只再降 0.002，平均分却又升了 1.98。前一段 loss 改善大，后一段任务成绩改善更大。

GR 的平均分为 54.66，动态 mHC 为 54.47，两者在这组实验中接近。0.19 个百分点的差距不足以证明普适的能力提升，选择 GR 还要结合内存访问和稳定性的结果。

### 5.3 GR 的实际读写流程

GR 使用四条残差分支。先对各分支独立做 RMSNorm，再结合全部分支的信息，通过低秩投影预测 sigmoid gate。这个 gate 对每个分支、每个通道分别赋权，随后将门控后的表示平均，作为当前子层输入。

写入则简单一些。每条分支得到一个依赖当前状态的标量 `s_i`，把子层输出 `y` 按 `R_i_next = R_i + s_i · y` 加回去。报告中的写入标量由 `2 × sigmoid` 产生，所以不能把所有 gate 都笼统描述成范围在 0 到 1。四条分支、逐通道读、标量写，各自对应不同的结构选择。（Eq.30-34，p11）

<TechGraph src="/images/posts/qwen38-next-技术报告深读/g05.svg" title="GR 的读写分工" caption="图解：逐通道门控读取与逐分支标量写入（博主自绘，基于原报告 §2.2、Eq.30-34，PDF 第 11 页）。" />

由于 GR 的读取内部已经做了归一化和门控，它替换了原来的子层 pre-normalization，而不是在旧归一化之前再叠一个完整模块。少了分支混合以后，各分支始终保持独立累积形式，也让跨层信息路径更容易分析。

这同样带来工程代价。四条分支意味着更宽的残差状态，要读写更多字节。删除 `H_res`、融合 read/write kernel、把状态从 BF16 存储改成 FP8，都是围绕这个成本做的选择。报告称 FP8 残差存储几乎不损失质量；这里讨论的是**残差状态存储**，不等于模型的每个权重、每个算子都在 FP8 中计算。

### 5.4 四条分支到底在保存什么

因为分支没有被 `H_res` 反复混合，作者能够把某个子层的读取分解为各个早期子层的贡献，再与不使用 GR 的参考模型比较。Figure 7 展示的是相对于参考模型额外增强的跨层路径。

<Figure src="/images/posts/qwen38-next-技术报告深读/p04.png" alt="GR 四条分支中的跨层路径，一条偏长程，其余偏局部" caption="来源：原报告 Figure 7，PDF 第 13 页；仅作忠实裁剪。线宽表示相对参考模型增加的贡献份额。" />

在这组 20 层模型分析里，一条分支主要承载长距离路径，另外三条较局部。作者在五个 GR checkpoints 中观察到同类分工，并举例说明早期 GDN 输出如何更强地进入后面的全局注意力层。额外宽度增强了特定路径，并未平均加强所有连接。（§2.2，p12-14）

这里的贡献份额是按实际前向 gate 值做的数值分解，并未通过删除某条路径来测因果贡献，也不能完整解释模型的语义知识。某条连接变强可以提供机制线索，要证明它导致了某项任务能力提升，还需要干预实验。

### 5.5 一个看似免费的优化为何被放弃

作者观察到分支使用不均衡，于是尝试只读取 gate 最大的两条分支。预训练 loss 和 benchmark 几乎不受影响，后训练后质量却明显下降；更复杂的稀疏方案也没有解决，最终未采用。（Inference Efficiency，p14）

只看预训练结果，少读两条分支是一个合理的减流量方案。后训练的退化却改变了这个决定：这里省掉的读取是否影响最终质量，需要沿训练流程继续验证。

## 6. N-gram Embedding：增加容量，不一定持续增加能力

### 6.1 查表为什么能成为一条新的容量轴

普通 token embedding 按当前 token 的 ID 查表。N-gram Embedding 则利用一个以当前 token 结尾的短序列作为地址信息，让局部上下文参与查找。相同 token 出现在不同局部组合中，可以获取不同的辅助表示。

表里存放的是训练得到的向量，与检索外部文档的 RAG 不同，不能为每个输出提供可追溯的事实证据。它的地址由 token 序列确定，可以在主网络计算到使用位置之前开始准备数据。

报告将额外表放到主机内存，并选在第 2 层接入，使预取可以与第 1 层计算重叠。（§2.3.1，p14-15）这个选择既考虑任务表现，也考虑执行顺序：太早使用，可能来不及搬运；更晚使用，是否有额外收益又需要实验。

<TechGraph src="/images/posts/qwen38-next-技术报告深读/g06.svg" title="查表地址已知，数据可以提前准备" caption="图解：N-gram 预取与第一层计算重叠（博主自绘，基于原报告 §2.3.1，PDF 第 14-15 页；不表示实测时延比例）。" />

Table 7 比较多个放置位置，并在固定表参数预算下试验同时放两层。单层方案已经有效，多层分配没有稳定收益；第 2 层表现较好，也适合预取重叠，作者据此采用单层。

从部署角度推导，预取能否完全隐藏开销取决于数据何时准备好、每步需要传多少向量，以及第一层提供多长的计算窗口。长 batch、不同 token 分布和不同互连都可能改变结果。因此，“可异步预取”是一个机制条件，不能直接翻译成“任何机器上都没有延迟成本”。报告没有提供足够的主机带宽与缓存命中数据，让我们为所有部署条件做这种保证。

### 6.2 先问预算有没有变，再比较结果

研究新增模块时，经常出现一个隐蔽问题：新方案比旧方案多用了参数或数据，却把结果完全归因于结构更好。这里的两张表把问题分得很清楚。

第一类是**固定总参数预算**：增加 N-gram 表时，减少 MoE 专家来抵消新增参数。问题是“同样大的模型，容量怎样分配更好”。第二类是**固定 MoE 规模，额外加表**：模型总参数增加。问题是“给现有主体增加查表容量，能带来多少收益”。这两类结论不能互相替换。

<Figure src="/images/posts/qwen38-next-技术报告深读/p05.png" alt="固定总参数预算下，调整 N-gram 和 MoE 参数占比的结果" caption="来源：原报告 Table 8，PDF 第 15 页；仅作忠实裁剪。增加 N-gram 参数时相应减少专家。" />

Table 8 中，loss 在 10 倍基础词表规模附近较好，但域外的 uncheatable PPL 变化很小，下游 benchmark 也没有显示对 MoE-only baseline 的明确全面改善。因此不能把这组数据读成“用查表替换专家已经被证明更优”。它更支持一个有限判断：两类参数承担不同角色，训练 loss 的最佳分配点不一定是任务能力的最佳分配点。

### 6.3 loss 单调下降，任务表现开始分叉

Table 9 固定 MoE 预算，逐步增加 N-gram 表。loss 随词表扩大持续下降，但 MATH、GSM8K 等任务在较小扩展后就开始饱和或波动；C-Eval、CMMLU 在这组实验里持续改善。不同任务对额外查表容量的响应并不一致。

<Figure src="/images/posts/qwen38-next-技术报告深读/d01.svg" alt="Table 9 中 loss、MATH、GSM8K 与 C-Eval 随 N-gram 词表扩大的离散数据" caption="数据来源：原报告 Table 9，PDF 第 15 页；博主重绘。保持 MoE 预算，增加总参数；各面板使用独立纵轴，仅展示原始离散点。" />

图中各任务单独展示，避免总分掩盖部分任务的下降。loss 与任务得分的含义和量纲不同，因此也使用独立纵轴。

以 MATH 为例，无额外表时是 32.52，20 倍词表时为 37.38，200 倍时为 35.34。最大的表仍比无表基线好，却没有保持早期增益的峰值。与此相对，loss 从 1.585 一路降到 1.526。仅看 loss，会错过继续扩大表容量带来的任务退化。

我们可以提出一种解释：局部模式的预测改善与复杂任务所需的泛化，并不总是同比增长。但这属于对结果的理解，报告没有把“某种模式记忆”对每项任务的因果贡献完整分离出来。也不能仅凭这个现象断言发生了测试集污染或过拟合；这些指控需要另外的证据。

容量预算最终要按目标任务来定。如果增加一倍表容量只改善训练 loss，业务相关任务却没有稳定变化，就需要算清新增存储带来了多少有效收益。查表省计算，仍要承担内存、传输和维护成本。

## 7. Muon 与训练配方：改了结构，就要重找合适的步伐

### 7.1 优化器依赖参数的含义和形状

Muon 对矩阵参数的动量进行近似正交化，再形成更新方向。报告使用 Newton-Schulz 迭代、Polar Express 系数安排以及八步迭代，把更准确的正交化与压力测试中的稳定性结合考虑。（§3.1，p16）

这与逐元素调整更新幅度的思路不同，矩阵的行列关系进入了优化过程。因此，“权重文件里是二维 tensor”并不自动意味着适合使用 Muon。一个矩阵也可能只是把语义不同的参数临时拼在一起，或者各维输出彼此独立。

| 参数类别 | 报告中的处理 | 阅读重点 |
| --- | --- | --- |
| Attention q/k/v、输出投影；专家主要线性层等 | Muon | 作为实际线性映射处理 |
| Token embedding、LM output head | AdamW | 未把所有二维矩阵一概交给 Muon |
| MoE router | AdamW | Muon 使早期波动加剧，后期尝试也无明显收益 |
| GR 的两个低秩投影 | AdamW | 作者将表现差异与细长矩阵形状联系起来 |
| N-gram embedding 表 | Adam，关闭 weight decay | 以 §3.1 的详细设置为准 |
| GDN decay、beta 等每 head 标量投影 | 不作矩阵正交化 | 需要从融合矩阵中按语义拆分 |

上表对应原报告 §3.1。对 router 原因的讨论是作者解释，不是已经普遍证明的优化器定理。某种参数不受益，可能与表示方式、训练阶段、学习率匹配和矩阵形状共同有关。

### 7.2 融合矩阵对计算方便，对优化未必方便

为了高效执行，训练框架常把 q/k/v 投影存成融合矩阵，把 SwiGLU 的 gate 与 up 部分也放在一起。对于前向计算，这能减少操作和调度开销；对于矩阵正交化，它却可能混合原本不应该共同处理的子空间。

报告采用先拆分梯度、分别正交化、再写回原布局的方法。qkv 与 GDN 输入投影细化到每 head；SwiGLU 的第一层拆成 gate 和 up。这里有两项变化：正交化尊重了子矩阵的语义，同时按真实子矩阵形状计算更新缩放，而不是使用拼接后的形状。

**存储时融合，优化时仍可拆分。** 参数放在同一块存储中，不代表它们必须接受同一次矩阵正交化。

### 7.3 分布式开销不能按参数个数平均

Muon 的每步计算量取决于矩阵形状。报告给出的 NS 运算量近似与 `max(A,B) × min(A,B)²` 及迭代步数有关。因此，两块包含相同元素数量、但形状不同的矩阵，正交化成本可能不同。按元素数均分到设备，会造成某些设备更慢，其他设备等待。

作者通过 Canzona 把逻辑优化器分工与物理参数布局分离，按估算的正交化 FLOPs 分配完整矩阵，再处理 tensor parallelism 下的重组和通信。拆分融合矩阵后，小 kernel 数量增加，又用 CUDA graph 减少启动开销。（§3.1 Implementation，p16）

比较优化器时，除收敛曲线外，还要记录 step time 的组成：梯度通信、矩阵重组、NS 计算、kernel 启动以及与 backward 的重叠。相同 tokens 下的 loss 更好，未必能抵消每步时间的增加。

### 7.4 稳定性改善之后，旧超参数可能过于保守

新架构和新优化器改变了适合的学习率与 batch size。继续沿用 Qwen3.5 的旧配方，能训练成功，并不意味着已用好新结构。作者重新拟合 scaling law，再把两种预测分开验证：小模型训练较多 tokens 来验证 batch，较大模型训练有限 tokens 来验证学习率。

batch 太大是否损害数据效率，需要有足够训练长度观察；学习率是否在规模增大后引发不稳定，则要在更大的模型上检查。同一个小规模短跑很难同时回答这两个问题。

<Figure src="/images/posts/qwen38-next-技术报告深读/p06.png" alt="4T token 预算下固定 batch 与 batch warmup 的训练 loss 对比" caption="来源：原报告 Figure 8，PDF 第 17 页；仅作忠实裁剪。左为固定 batch，右为逐步增大 batch。" />

在 20 层、10.8B-A0.89B MoE、4T tokens 的测试中，预测 batch 为 25.2M tokens，旧配方为 12.6M；相应学习率也按配方匹配。最终 loss 的改善约为 0.0072，再把 batch 提高到 37.7M，loss 只略微变差。结果支持一个“较平坦的合适区间”，不应解读成精确到最后一位的小数最优常数。（§3.2，p17）

较大模型验证使用 48 层、156B-A7B MoE 和相同的 419B-token 预算。新的预测点及附近设置在 loss 上接近，且优于旧配方；Table 10 的任务平均分也支持新配方。作者同时指出评测次数和窄幅差距的限制，所以不能把前列几个设置的排序写成确定的统计结论。（p18-19）

### 7.5 不再需要的是哪一种 warmup

作者重新测试 batch-size warmup：从较小 batch 逐步增加到 25.2M，既试了保持目标学习率的版本，也试了为小 batch 降低学习率的版本。它们最终没有优于从目标 batch 开始训练，却为了处理同样多的 tokens，多消耗了 18.8% 的优化器 steps。（§3.2，p18）

<Callout type="note" title="这里取消的是 batch-size warmup">

报告仍展示 learning-rate warmup。逐步增大 batch 与逐步提高学习率是两种安排，不能把这一结论缩写成“Muon 不需要 warmup”。18.8% 也是额外 optimizer steps 的比例，不是实测的训练总费用下降比例。

</Callout>

更少的 steps 可能减少通信和调度次数，较大的 batch 也可能改善设备利用，但单步时间还会随 batch 改变。实际节省多少，仍要看墙钟时间和资源用量。

## 8. 压力测试、最终成绩与工程判断

### 8.1 小规模正常运行，为什么还不够

训练不稳定可能很晚才出现。模型更大、训练更久，在高学习率区间停留的 steps 更多，都会让一次小规模短试验看不到的异常暴露出来。等完整训练再发现问题，代价往往已经很高。

报告通过在中等规模模型上持续使用较高学习率，把压力提前暴露出来。测试比较 Qwen3.5 结构配 AdamW、相同结构配 Muon，以及 Muon 加 GR；模型为 28 层、25B-A3B，batch 和梯度裁剪阈值保持一致。作者观察 loss spikes、裁剪前梯度范数和最大激活值，明确规定 spike 是相对 201-step 滚动中位数高出 0.1 的 step。（§3.3，p19-20）

<Figure src="/images/posts/qwen38-next-技术报告深读/p07.png" alt="在两倍和四倍最优学习率下，AdamW、Muon、Muon 加 GR 的训练曲线" caption="来源：原报告 Figure 10，PDF 第 19 页；仅作忠实裁剪。为固定高学习率压力测试，不是常规生产学习率建议。" />

在四倍最优学习率的压力下，AdamW 基线每一万 steps 发生 183 次 spikes；Muon 加 GR 的配置没有记录到 loss spike，两个 Muon 配置均未越过梯度裁剪阈值。这支持“新配方在所测压力下更稳定”，但不能得出“任何模型都可以把学习率直接乘四”。测试中的倍数是在特定模型和定义下构造的压力，不是通用调参公式。

### 8.2 分开检验组合收益与 gate 的作用

组合方案表现好之后，还要问是谁在起作用。作者另做了一对保持 AdamW、结构和数据顺序不变的实验，只切换 GatedNorm，在三倍最优学习率下，spike rate 从每一万步 32.0 降至 3.2，阈值越过次数从 256 降至 20。（Figure 12；§3.3，p20-21）

这比仅比较“旧配方”和“全新配方”更接近门控作用的单变量证据。不过 GatedNorm 单独试验与完整 GR 方案仍有层级区别，不能把全部稳定性提升都归到一个简化模块上。

作者认为，网络在高学习率下需要有效的重缩放方式。缺少显式 gate 时，可能通过增长激活异常值实现，因而更脆弱；乘法门控提供了更直接的缩放路径。这是作者对机制的解释，spikes 和激活值的观测本身还不足以完整证明它。

### 8.3 压力测试之后，再看生产配置

提高学习率的压力测试适合快速筛选，但毕竟离开了真正使用的配置。因此报告又比较生产训练前 276B tokens：相同数据顺序、学习率安排和优化器下，比较 Qwen3.5 加 Muon、进一步加 GR、以及完整 Flash-Next 配方。

Figure 13 在这个窗口内展示 loss、梯度范数和残差最大激活值。加入门控后的配置波动更小，完整配方也取得更低 loss。作者另外报告完整训练没有出现 loss spike 或梯度范数异常。（p21-22；Introduction p3）

这两类证据应分开陈述：公开绘制的受控对照是生产训练早期窗口；关于完整训练平稳完成，则是作者的报告。不能把早期三条对照曲线误写成整个训练周期都做了相同的全量并行对比。

报告没有依赖 qk-clip、SwiGLU-clip 等显式激活控制来维持上述稳定性，也不意味着“完全没有梯度裁剪”。多处实验仍设置了 0.5 的梯度范数阈值，并统计触发情况。没有触发、配置了但无需依赖、彻底没有这一机制，是三种不同状态。

### 8.4 最终成绩支持什么

### 8.5 把消融结果放回各自的尺度

报告覆盖了多个模型规模和训练预算，这是优点，也增加了一种误读风险：读者可能把每节最好的数字都当成同一模型上的累积增益。

| 设计问题 | 报告使用的关键实验设置 | 合适的理解 |
| --- | --- | --- |
| Full / SWA / GDN | 25B-A3B；400B + 80B tokens | 检查 token mixer 选择 |
| QSA 压缩比、索引头数 | 35B-A3B；CPT 后评测 | 检查稀疏索引设计 |
| 残差读写 | 25B-A3B；560B tokens | 检查读写表达方式 |
| GR 信息路径 | 20 层配对模型 | 分析跨层贡献结构 |
| Batch 预测 | 10.8B-A0.89B；4T tokens | 检查较长训练下的 batch 设置 |
| Learning-rate 预测 | 156B-A7B；419B tokens | 检查更大模型的配方外推 |
| 最终 Base 成绩 | 125B 主体 + 51B 表 | 检查整套方案的输出结果 |

这些表里的平均分增益不能相加。组件存在相互作用，基线、训练量、评价任务也不完全相同。作者先在可承受的规模下筛选，再用不同规模的测试检验风险，最后评估完整配方。

### 8.6 工程上可以怎样采用这些认识

做架构研究时，可以借用报告的**验证顺序**：先选一个具体问题，再建立对照。想减长上下文开销，就同时记录索引和 core attention；想改残差，就同时看任务成绩与激活行为；想换 Muon，就把 step time、参数形状和更新语义一起纳入检查。

对于训练试验，保留一组能揭露后期行为的探针很重要。报告里的 NoPE 和稀疏分支读取，都可能通过早期 loss 检查。一个较小但贴近最终使用方式的后训练检查，比在预训练 loss 上多争论第四位小数更有决策价值。这是本文基于负结果提出的建议，不是报告已经证明存在某个万能的代理指标。

如果目标是部署，验收则应围绕真实请求分布展开。建议固定模型 revision、推理框架版本、权重量化、上下文长度与并发，再把成本拆成以下几项：

- **Prefill**：记录首 token 延迟，分别看短输入与长输入，检查 chunked prefill 的调度行为。
- **Decode**：记录每 token 延迟和总吞吐，核对 MTP 是否启用、接受长度及验证代价。
- **内存与传输**：记录 GPU、Host 占用及峰值，检查 N-gram 预取是否真正隐藏在计算后面。
- **任务质量**：固定抽样任务、生成预算和判定方式，特别保留长距离引用、工具失败恢复与终止行为。

工作负载和执行环境会改变这些设计的收益。比如，QSA 对极长输入很有价值，但日常请求很短时，服务开销可能主要来自别处；Host 表容量充足，设备互连却弱，异步预取也可能无法完全遮住数据搬运。

服务迁移可以优先比较相同任务成功率下的延迟与成本。如果新配置更快，却增加错误引用、重复生成或工具误用，就应把返工和失败成本一并算进去。

### 8.7 这份报告仍没有回答的问题

最明显的缺口是完整训练与后训练配方。报告对架构消融、QSA CPT 和优化器细节给出了较多内容，但训练语料组成、全部生产配置、后训练过程和评估材料仍不足以让第三方按文档完整复现模型。公开一个结构，不等于公开全部能力来源。

第二个缺口是端到端部署证据。注意力内核结果相对明确，但仅凭这些图无法回答一组具体硬件能承载多大并发、Host 表查找会增加多少尾延迟、不同量化策略如何影响任务成绩。本文因此没有给出 GPU 数量或美元成本推荐；这些需要在明确硬件和业务输入之后实测。

第三个问题是结果的可迁移性。适用于这个模型与数据配方的门控、词表规模和 batch 安排，换到更小模型、更少数据或不同语言分布，排序可能变化。尤其 N-gram 的实验已经显示任务响应分化，不能从一组平均结果推导所有场景的容量分配方案。

第四个问题是评价效率。作者在结尾指出，如果能找到更便宜、又能可靠预测后训练排序的中等规模探针，就能搜索更多设计。这个开放问题贯穿全文：架构实验的瓶颈不仅是算力，也是我们需要到多晚才能知道自己选错了方案。

## 9. 我的判断：值得学习的是怎样让取舍接受检验

这份报告让我更重视三种设计习惯。

**第一，把算术工作量和数据搬运一起设计。** GDN 的状态、QSA 的索引、GR 的分支以及 N-gram 的主机内存，分别改变计算与存储关系。只统计 FLOPs，无法解释所有时延；只看参数量，也无法解释哪些容量必须驻留设备、哪些可以按需准备。

**第二，稳定性会影响学习率与 batch 的选择。** 门控如果让训练承受更合适的学习率与 batch，就可能提高训练效率。这条链上的每一环仍要分别验证，平滑曲线并不直接等于更强泛化。

**第三，把未采用的方案也写下来。** 部分任务下降、后训练退化、额外组件无收益，这些结果解释了作者为什么放弃某条路线，也能帮助后来的人判断是否值得重试。

Qwen3.8-Next 报告保留了从局部改动到完整配方的实验过程。沿着这条过程，读者可以核对每项收益发生在哪里、在什么条件下测得，以及进入后续训练或部署后是否仍然成立。
